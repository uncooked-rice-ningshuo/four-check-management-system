# 周通报唯一维护部门实施方案

> 2026-11-14：用户已确认采用唯一维护部门方向；本文为实施方案及交付记录，代码与迁移 058 已实现，隔离环境已验证，目标环境尚未加载。当前分支 feat-0.1-3，工作区已有其他任务改动，实施时保留。本文覆盖默认权限方案中“多个部门可同时承担周通报”的旧设计。

## 1. 结论与首期范围

复用 department_report_scopes.enabled 表示维护资格，全局至多一个部门为 true；现有初始化选择学生会办公室。正常使用时保留一个有效维护部门，不允许通过普通保存关闭最后一个维护部门，也不允许停用该部门。所有岗位动作关闭不释放维护资格。

首期完成唯一约束、重复开启提示、权限防绕过和停用保护。保留现有部门动作与岗位动作交集、委员和负责人职责分工。日常检查提交、审核批次不受影响；REPORT_VIEW 与 ARCHIVE_VIEW 的独立个人授权继续按原范围处理，不自动给其他部门增加查看权限，也不新增只读模板编辑功能。

跨部门移交不作为首期必需功能：当前强制生成和应交管理明确绑定 OFFICE 负责人，直接迁移普通维护资格会产生部分功能不可用的问题。未来移交须另行确认这两项资格是否改为“维护部门负责人”，并实现原子移交及新岗位模板确认；首期不提供先关后开的替代操作。办公室默认且当前负责，不增加部门名称硬编码来实现唯一性。

## 2. 实施前实现与缺口（历史基线）

- 迁移 057 建立 department_report_scopes，并默认启用办公室；当前没有跨部门唯一索引。
- store/department_defaults.go 的 SaveDepartmentDefaults 在审计事务内更新部门 permission_version、业务范围和岗位模板，并使该部门会话失效；不同部门版本号互不约束，因此不能防跨部门同时启用。
- permission.Service.Effective 将周通报默认动作授予无部门范围的报告权限；个人允许规则独立计算，单改开关不能保证维护职责唯一。
- organization.UpdateDepartment 当前没有维护部门停用保护。
- isForceGenerateEligible / isReportObligationManagerEligible 仍要求办公室部长或副部长；超级管理员保留已有例外，不因本次变更扩大特殊权限。

## 3. 数据库与升级

追加下一空闲编号迁移，不改写 057。使用部分唯一索引：

```sql
CREATE UNIQUE INDEX department_report_scopes_one_enabled
ON department_report_scopes ((1)) WHERE enabled;
```

索引保证至多一个启用部门，包括两个管理员同时保存的情况；不能单靠它保证至少一个。关闭最后一个、停用维护部门由应用事务规则保证。停用部门与开启维护资格必须锁定同一部门行，重新检查 enabled，避免并发绕过；现有权限版本校验保留。

升级前只读盘点启用部门、有效性、办公室存在性、岗位配置和非维护部门个人写权限。正常情况只有有效办公室，直接增加索引。若已启用多个部门、唯一部门不是实际负责的办公室、维护部门已停用，或缺少维护配置，停止升级并输出脱敏冲突清单，不静默选一个、清空配置或扩大岗位权限。零配置的既有库须明确修复后升级；全新库由既有初始化生成办公室配置。迁移失败应整体回滚，历史报告、快照、审计不改写。

## 4. API 与事务规则

沿用现有默认权限读取/保存接口。读取增加必需的 reportMaintenance 摘要：状态（assigned/unassigned）、departmentId、departmentName。客户端缺字段或读取失败显示配置加载失败，不把失败当成无人维护。摘要由服务端查询，保存不能信任客户端提交的归属。

保存规则：

1. 维护部门保存原 enabled=true 及岗位配置正常执行。
2. 其他部门 enabled=false 的日常检查配置正常保存；其已有通报模板保留但不生效。
3. 其他部门尝试 enabled=true 返回 409 / REPORT_MAINTENANCE_ALREADY_ASSIGNED，提示“周通报已由学生会办公室维护，不能重复开启”，部门名取实际配置。
4. 当前维护部门尝试关闭返回 409 / REPORT_MAINTENANCE_REQUIRED；尝试停用返回 409 / REPORT_MAINTENANCE_DEPARTMENT_IN_USE。
5. 无维护部门的合法首次配置只允许有效部门；并发争抢由唯一索引兜底，只有一个成功。升级异常不通过该路径自动修复。
6. 原有版本冲突沿用现有码；无管理权限仍为 403；未知数据库异常为 500，不降为输入错误。仅将指定唯一索引冲突转换为上述占用码。

任一步失败都回滚部门版本、检查配置、岗位配置、会话变化和成功审计，不能半保存。所有入口使用同一业务服务。业务事务内读取关键前值并审计，避免用过期预读结果记录错误前值。

## 5. 权限防绕过

普通账号生成草稿、修正、审核、退回、定稿、输出设置和发起定稿更正均须满足：可信主部门为当前有效维护部门，再按原有岗位、默认动作/个人例外、数据范围、状态及版本规则判断。非维护部门的普通账号不可获授维护权限；非维护部门的系统管理员（被授权账号的系统角色为 ADMIN）可逐动作单独授权，默认不获得维护能力，也不会使其部门成为第二维护部门。个人拒绝继续生效。

个人授权页面根据服务端返回的可授予动作禁用不合格选项；新增和修改授权接口都在保存前拒绝给非维护部门普通账号授予这些写动作；有效权限计算同时过滤既有不符合资格的允许规则，以覆盖历史授权和后续调岗。原规则保留可追溯，不删除历史记录，权限详情解释“不属于当前维护部门，未生效”。调岗和配置变更沿用会话失效机制，盘点受影响的跨部门个人授权账号并覆盖其缓存/会话失效。

REPORT_GENERATE 当前同时控制文件生成，因此非维护部门普通账号不能通过个人允许生成报告文件；获单独授权的系统管理员可按相应动作和范围执行；已有文件读取、下载继续按原有查看权限、关联版本和文件状态鉴权，不隐式增加下载资格。强制生成、应交配置仍要求办公室负责人、维护资格及单独授权。发布未交付，本轮不开放入口；保留的权限码也不能成为绕过维护资格的渠道。超级管理员原有能力保持，界面明确唯一的是业务维护部门，不宣称取消系统特权。

需要检查 reporting、reportoutput 和归档更正入口，确保所有写路径使用收紧后的权威权限。历史定稿、冻结数据和来源部门不随资格变化改写。

## 6. 页面交互

沿用默认权限页和“部门功能 / 角色权限”入口。

- 办公室显示“当前维护部门”；承担状态不可直接关闭，解释“周通报须保留维护部门”。部门动作与角色权限继续可编辑。
- 其他部门承担开关禁用，并在行内显示“已由学生会办公室维护，不能重复开启”；不只依赖悬浮提示。维护动作编辑入口禁用，日常检查编辑保持正常。
- 全部岗位动作关闭时提示“当前没有生效的岗位动作”，仍显示办公室占用维护资格；不擅自强制开启某项岗位权限。
- 首次未分配可选择有效部门；加载失败显示重试，不开放开关。
- 保存发生归属冲突后刷新维护摘要，保留未保存检查配置，明确本次保存整体未成功；用户核对后可重试。
- 保存成功使部门默认配置、归属摘要、有效权限等关联查询失效。禁用状态和原因支持键盘读取，窄屏提示完整显示。
