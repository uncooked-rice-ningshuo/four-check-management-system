# Task 6 / Task 7：导航与工作上下文

## 范围与决策

沿用已确认的 `/` 工作台及统一应用外壳，不增加导入、审核或统计一级导航，也不开放尚未完成的检查页面。导航和路由的动作判断现在扣除完全覆盖 ALLOW 的 DENY；局部 DENY 不误伤剩余可用范围。具体检查类型/班级/周次仍由页面请求及服务端进行权威范围检查，导航本身不是授权边界。

临时工作周按技术方案的全局 system_settings 保存，影响系统默认工作上下文；不重写校历和已有记录，不覆盖用户已经打开的表单或已经选择的业务范围。管理入口沿用现有校历管理权限，仅超级管理员操作；普通系统管理员不因角色名称获得新的校历权限。

## API 和数据

追加 `013_work_context_settings.sql` 创建 system_settings，并预置 work_week_override 配置，初始版本 1。后续部门流程迁移顺延为 014。

- GET /api/v1/work-context：需要有效登录且已完成初始密码修改，返回 week（含 semesterId，可能为空）、source、version，以及生效覆盖的 expiresAt。
- PUT /api/v1/work-context：超级管理员操作。请求为 weekId、expiresAt、version、reason。启用覆盖必须提供启用的目标周 UUID 和未来的 RFC3339 到期时刻；恢复校历传 weekId 为空、expiresAt 为 null。版本正整数，原因非空且最多 255 字。
- source 为 CALENDAR、OVERRIDE 或 NONE。到期时刻立即失效；目标周、学期或学年停用时回退至正常校历；没有有效教学周返回 NONE/空 week。
- 403 表示无管理权限，409 VERSION_CONFLICT 表示并发版本变化，422 VALIDATION_FAILED 表示参数或目标无效，500 返回安全提示。

服务端以北京时间判断业务日期，日期边界不依赖数据库会话或浏览器时区。覆盖保存先锁定配置版本，再锁定有效周次及父级，更新配置和写入校历审计同事务完成；审计失败不改变值或版本。自然到期不执行后台写入，按保存的到期时间在读取时计算。

现有 /academic/current-week 与工作台的默认上下文已统一使用相同解析逻辑。工作上下文条每 30 秒向服务端刷新，变化时使工作台及默认周次缓存失效；不在浏览器自行计算当前周。管理表单明确显示“全体用户”影响、到期时间（北京时间）与原因，打开时捕获版本，后台刷新不会替换正在编辑的版本。

## 验证与边界

领域测试覆盖正常校历、覆盖优先、到期边界、空教学周及无权修改；HTTP 测试覆盖未登录、读取、管理更新、403 和版本冲突。真实临时 PostgreSQL 空库执行 001–013，验证启用覆盖、清除、过期、父级停用、北京时间跨日和审计失败回滚。集成命令：

```bash
cd server
WORK_CONTEXT_TEST_DATABASE_URL='<一次性空库连接串>' GOTOOLCHAIN=go1.25.0 go test ./internal/store -run TestWorkContextPostgres -count=1 -v
```

测试检测到已有 accounts 表时拒绝修改。未在业务数据库执行迁移。前端通过独立组件测试覆盖加载、空数据、失败重试及恢复校历请求版本；导航及路由测试检查 DENY。真实浏览器跨角色验收仍需在后续整体门禁中完成。
