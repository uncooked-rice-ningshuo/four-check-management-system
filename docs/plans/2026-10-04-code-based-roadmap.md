## 历史建议顺序与完成条件（由最新五类范围决定覆盖）

1. **卫生区域配置（10-04 代码与隔离增量已验，目标环境待加载）**：复核后端按部门和检查类型授权、审计与失败路径，在一次性 PostgreSQL 验证；补前端类型、客户端、授权入口及新增/编辑/停用/历史交互。完成条件是管理员和受限部门管理员分别通过真实浏览器操作，越权写入被服务端拒绝。
2. **两类卫生页面（代码与隔离增量已验）**：按公共宿舍卫生、教室卫生顺序实现关联选项、列表筛选、详情、新增、草稿编辑/删除和失败状态。每类完成真实 PostgreSQL 与浏览器操作顺序回归，且不开放无权入口。
3. **部门工作流（分组粒度待确认）**：按用户确认的同一提交递增版本并保留每次修订，加迁移、聚合、显式状态机、提交/审核/退回/确认 API、审核视图和工作台联动；确认后记录不得任意重开。以并发冲突、越权、事务回滚和跨角色 E2E 为门禁。
4. **六类导入与确认重校验已验，当前补公共宿舍卫生**：按六类逐个交付黄金模板、解析校验、预览、确认与错误反馈；按用户确认的整批、全部未提交且未锁定草稿基线实现安全撤销，保留原文件与审计。逐类验证字段、权限、重复和故障恢复。
5. **关闭阶段二总门禁**：修复认证刷新中断问题，统一错误契约；在一次性 PostgreSQL/MinIO 与真实浏览器执行七类、部门流程、导入/回滚、角色和故障矩阵。局部通过不等于阶段完成。
6. **阶段三统计与通报**：先确定统计口径与结构化快照，随后完成草稿生成、锁定、审核退回、链路内修正、定稿 Word/Excel 文件快照、发布、更正和历史归档。以历史数据不随基础数据变化、文件故障可恢复及权限/审计为门禁。
7. **阶段四目标环境交付**：核对部署版本、迁移、模板、对象存储和初始化数据；执行角色验收、联合备份恢复、安全与性能检查后再认定上线准备完成。
