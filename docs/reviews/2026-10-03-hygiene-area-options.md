# 两类卫生区域关联选项增量（2026-10-03）

教室卫生与公共宿舍卫生已进入现有 `context-options` 和 `entry-options`。前者提供教室、所属启用区域及该检查类型的原因字典；后者提供完整楼栋/楼层/区域名称、同楼栋启用责任寝室及原因字典。两者复用责任班级上的学年、学期、周、检查类型、部门、班级、年级 ALLOW/DENY SQL 判断；编辑选项沿用草稿所有权和独立管理权限。历史查看上下文从已保存的责任班级投影。

授权后返回的检查记录增加当前区域名称；公共宿舍卫生还返回责任寝室当前名称。责任班级/学生继续使用记录时的名称快照，区域/责任寝室当前名称不能直接当作未来定稿快照。

验证：`go test ./internal/inspection ./internal/store`、`go vet ./...`、`go test ./...` 通过；`TestInspectionPostgresCRUD/area_hygiene_scoped_options` 在一次性本机 PostgreSQL 16 中通过，验证类型匹配、授权/拒绝、关联对象、原因字典和新增记录展示。目标业务服务未加载此代码，区域维护入口和页面尚未交付。

用户确认区域维护可由基础数据管理员和对应检查部门管理员共同承担，需支持可配置授权。现有 `MASTER_DATA_MANAGE` 有可配置范围，但通用基础数据路由以空范围验权；下一项须为区域专门按目标部门及检查类型验权，不能让部门范围授权扩成所有基础数据管理。区域关联仍由数据库外键和后端校验保护。
