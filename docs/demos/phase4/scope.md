# 当前评审版（2026-11-15，按用户确认调整）

当前 Demo 为五个页面：学期违纪台账、待处分、处分归档、处分规则、文书模板。后两项归入处分配置。

学期台账包含未达标和零违纪学生；待处分只处理尚未确定的事项；确认后进入处分归档，文书制作从归档记录发起。归档入口表示已确定结果库，不等于学期只读封存。原独立文书制作、我的待办和辅导员绑定演示入口已移除，绑定仍属于基础配置需求。

Demo 支持搜索、学生详情、角色范围切换、同意/延缓、确认后移入归档及三步模拟出文。全部为虚构内存数据，刷新重置；模板与规则目前仅预览。JavaScript 语法检查通过，浏览器连接超时，视觉与真实点击尚未完成验证。

以下为首版历史方案，页面结构已由上述决定替代；功能需求与待裁决项仍供参考。

# 阶段 4：处分管理范围与页面提案

2026-11-15；基于用户提供的 V5.0 需求。设计评审稿，不构成对冲突业务规则的确认。

## 项目实际与边界

当前分支 feat-0.1-3。已有 .env.example 修改及 docs/proposals/ 未跟踪内容保持不动。依据项目状态 11-14 摘要与路由/通报源码，八类检查、确认批次、周通报与输出已有实现，最新权限增量仍有目标未部署/角色待验收边界。此处不重复开发八类录入与四查汇总，也不把历史部署记录当作当前环境验收。

既有周通报输出已改为即时生成下载；处分必须新增持久化文书版本、编号、发送与归档链路。可复用认证、学生/班级/学期、检查确认来源、审计、文件基础设施、模板渲染经验；不能直接将周通报草稿修正当成处分权威事实。旧规划“阶段四上线准备”与本轮“阶段4处分管理”名称需在正式计划中明确替换关系，本稿采用后者。

## 功能清单

1. 累计与判定：八栏独立按学期累计；仅已确认违纪；到课按学时、晚自习按次、卫生仅不合格、无机课堂沿用处罚计次与去重。保存来源修订、规则与明细快照。
2. 规则管理：累计项、区间、适用年级/专业、学期、启停、版本；实际执行封顶记过。未完成案件重判、已出文不回溯。
3. 合并配置：按学期拖拽组合/拆分、命名、互斥校验与审计；本期不合并，延缓案件保留原口径。
4. 条款库：按栏与级别匹配，制度、字号、章条款、全文、历史版本；缺失条款阻断出文。
5. 案件清单：学生聚合、项目展开，多维筛选、来源详情、重复提示、推送/重推、忽略理由、管理员调整级别、筛选导出。
6. 辅导员基础配置：新增业务身份及学期班级绑定、多辅导员、Excel 预览确认导入、待指派、调岗任务转交；范围必须服务端校验。
7. 我的待办：核对事实、附件、同意/延缓、批量确认预览、二次确认、限时撤回留痕、多人并发保护。
8. 任务与通知：即时警告推送、周结算、提醒、超时自动确认、延缓重推、记过封顶、失败重试与幂等；站内必选，外部渠道可选且需另行授权。
9. 通报批评：周首次达标去重、补出、名单排除留痕；每栏决定 + 一个合并告知书，不占号；固定配置排序、每页两份、单人文案、不同落款；生成与发送分离。
10. 处分决定：权限和前置条件校验、三步向导、事实措辞可编辑但数字只读、模板版本、同源预览、DOCX、可选 PDF。
11. 文号与文件：年份 × 文种并发分配、预览不占号、失败恢复、作废不复用、连续性检查、限时撤销条件、历史版本与更正件。
12. 送达：依班级绑定自动发送、可配置抄送班主任、记录发送/已读；出文后仅通知，不再创建确认待办。
13. 台账与学生档案：文书台账与学生处分记录双视图、筛选导出、历史学期只读、全流程归档；本期不做解除处分。
14. 验收：真实 PostgreSQL 事务/并发/隔离；跨角色浏览器闭环；定时任务重试；文件字段、排序、分页、版本一致性及真实 Word/WPS 检查。

## 页面结构建议

| 归属 | 页面 | 核心结构 |
|---|---|---|
| 既有工作台 | 我的处分待办 | 本人待办、剩余时限、一键确认；详情抽屉核对与结论 |
| 处分管理 | 待处分清单 | ProTable 筛选 + 学生行 + 累计项子行；案件详情抽屉含来源、规则、历史与流转 |
| 处分管理 | 文书制作 | 通报批评 / 处分决定 Tab；周名单、生成队列；处分三步向导 |
| 处分管理 | 台账与存档 | 文书台账 / 人员档案 Tab；详情含版本、文号、送达、审计 |
| 系统配置 | 处分规则 | 累计项与合并 / 区间 / 条款 / 模板与文号 Tab；不同动作分权 |
| 基础数据 | 辅导员班级绑定 | 学期、辅导员、班级、状态；导入与映射异常处理 |

Demo 将六个入口平铺便于评审；正式系统沿用单一工作台和权限侧边栏，导入、审核、统计不新增一级导航。列表落地复用 ProTable，状态由 TanStack Query 管理。

## 实施前需要裁决的冲突

- 2 个工作日 vs 连续日历日且节假日不顺延；提醒与截止必须采用同一时钟口径。
- 延缓案件累计变动即时重推 vs 多处每周结算重推；Demo 采用后者，仅为展示假设。
- “解锁后修正已锁定来源”与仓库不可直接修改锁定/定稿数据冲突，应走来源更正与新版本，不在本轮实现解锁。
- 规则变化重判未完成案件 vs 已完成判定不变，以及延缓保留旧累计组：需定义版本边界。
- 同时命中规则取最高，应明确限于同一累计项；不同累计项仍分别判定和出文。
- 只增不减 vs 修正重算可能减少：需明确纠偏与撤案行为。
- 初始条款正文说三栏待补，表格只有晚自习与无机课堂两栏；需补齐权威材料。
- 生成后 24 小时未打印可撤销，但下载后的实际打印无法可靠检测；需明确可执行判据及与自动送达关系。
- 已下达处分的档案写入时点、已生成/已送达/案件状态分离、文件一对一与更正多版本关系需明确。
- 现有岗位显示部长/副部长，需求称主任/副主任：必须绑定现有组织角色与有效动作，不能靠中文名称鉴权。

## 建议交付顺序与完成条件

先冻结上述状态/时间/数据口径及真实模板，再做辅导员绑定与规则版本；随后累计案件与待办，接着周结算和三类文书，最后文号送达、档案及全链路验收。每批分别记录模型/迁移、API、页面、模板/初始配置、真实环境、角色验收，不能以 Demo 代替交付。

本轮仅交付范围提案与独立 HTML Demo；不修改运行时代码、不迁移、不部署。Demo 支持入口切换、模拟角色、搜索、详情、同意/延缓及制作向导；规则编辑、拖拽、真正文件生成和通知均未实现。所有学生为虚构，状态仅存在内存。
