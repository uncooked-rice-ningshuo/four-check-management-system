## 执行顺序与退出条件

### 1. 历史基线增量与仍未关闭的认证恢复

错误批次重新上传、确认范围业务名称、失败同键重试及 409 后刷新已完成；35 组真实服务 E2E 和 163 项前端测试通过，见 [重传验收](../reviews/2026-09-21-import-recovery.md)。不再将它们安排为待开发。

认证跳转诊断已完成：两轮各 12 次自然跳转分别失败 5/7 次，响应丢失对照验证上游轮换 200、旧 Cookie 重试 401。见[诊断记录](../reviews/2026-09-21-auth-navigation.md)。现象未修复，恢复方案仍需保持单次消费安全语义，不能通过调整测试导航或放宽重放规则宣称解决。该时点随后推进的角色/故障矩阵已有局部验收；认证恢复仍未完成。

现有到课率部门范围、个人 DENY、跨部门模板下载/批次确认、权限变更会话失效及真实 MinIO 暂停恢复已通过，见[角色/故障矩阵](../reviews/2026-09-21-role-storage-matrix.md)。确认 409 与提交成功但响应丢失也已有真实服务证据。管理模块仍只验证代表性写操作，十二类列表通过不等于每项管理动作全部验收。Compose readiness 配置门禁已修正并通过解析/接口测试，未启动或替换业务服务。目标环境发布待授权期间，可独立推进 D1 已确认的无机课堂页面；认证恢复方案和其余业务矩阵继续保留未完成。

退出条件：认证边界具有可重复结论，确认的缺陷有修复与回归；剩余权限/故障场景有真实 API/浏览器证据。故障注入与真实失败分别记录，每次修复经过匹配的聚焦及完整检查。

### 2. 应用到本地目标环境，关闭 Task 0 的运行缺口

先核对实际 API 所连数据库及迁移、应用 MinIO 凭据和已启用超级管理员，准备具体发布命令与回退/诊断步骤。按仓库要求，在执行目标模板发布及服务替换前取得对应授权；不得把隔离测试授权扩展为业务发布授权。

加载当前 API 和前端，发布到课率模板，使用实际角色检查模板下载及页面入口。写入验收优先使用已建立的隔离数据环境，不对真实学生制造测试违规。

退出条件：运行版本、迁移、模板、API、浏览器与角色证据齐全。readiness=200 只是依赖就绪，不能单独关闭门禁。

### 3. 补卫生区域配置与剩余三类页面（Task 10A/10B）

用户已确认卫生区域可由基础数据管理员及对应检查部门管理员维护，按可配置权限决定。录入选项读取权限与配置管理权限分开；只读关联选项已验。按既有 masterdata 层次补区域维护，不让用户手填 UUID。

目标运行环境发布与卫生区域权限归属尚待具体授权/确认期间，先独立推进已确认 D1 的无机课堂。09-21 代码复核发现通用详情只有关联 ID，且缺少普通录入人员的学生/课程/教室授权选项 API；管理级 master-data 接口不能直接作为成员录入入口。先补应用服务/仓储层的范围过滤选项与名称展示契约，再接页面，查询应在 SQL 中扣除 DENY，覆盖分页，不扩大管理权限，也不要求手填 UUID。此为既定页面可操作性的前置能力。学生/班级持久化快照已加入创建/详情/列表/编辑响应，并验证学生改名不会改变原快照；到课率/无机课堂的范围关联选项已接通并通过七维 DENY 与分页回归；课程/教室当前名称已补并通过隔离验证（见[记录](../reviews/2026-09-21-inspection-current-labels.md)）；普通成员页面上下文已通过[权限/分页回归](../reviews/2026-09-21-inspection-context-options.md)，无机课堂页面已通过[真实浏览器验收](../reviews/2026-09-21-unattended-classroom-page.md)。

AuthProvider 切号缓存问题已复现并修复，同浏览器回归与前端全量通过，见[验收记录](../reviews/2026-09-21-auth-query-cache.md)。晚归[授权关联选项已通过后端验收](../reviews/2026-09-21-late-return-options.md)，宿舍当前名称已通过[隔离回归](../reviews/2026-09-21-late-return-labels.md)，晚归页面已通过[验收](../reviews/2026-09-21-late-return-page.md)，早锻炼/早签[前置选项已验](../reviews/2026-09-21-morning-options.md)，早锻炼/早签页面已通过[10-03 隔离浏览器验收](../reviews/2026-10-03-morning-attendance-page.md)。宿舍卫生前置授权选项与责任快照已通过[10-03 真实 PostgreSQL 验收](../reviews/2026-10-03-dormitory-hygiene-options.md)，独立页面已通过[隔离浏览器验收](../reviews/2026-10-03-dormitory-hygiene-page.md)。两类区域的授权只读选项已通过[真实 PostgreSQL 验证](../reviews/2026-10-03-hygiene-area-options.md)。用户确认基础数据管理员及对应检查部门管理员均可维护，需可配置授权。下一项补区域维护模型、按部门/检查类型范围鉴权的 API、审计与入口，再按“公共宿舍卫生 → 教室卫生”逐类落地剩余页面，复用已有七类 API、ProTable 和草稿操作能力。每类独立交付列表、筛选、详情、新增、修改、批删、空/失败/无权限状态及 E2E。实施时重新核对字段目录和原型，不新增未经确认的业务流程。

### 4. 部门流程（Task 8–10，联动 5/11/12）

先确认退回重提是同一提交递增版本还是新修订，再补迁移、聚合、事务状态机、版本/幂等、审核视图及工作台联动。确认后的更正不得直接重开定稿或确认数据。

退出条件：提交→审核→退回→修正→重提→确认，以及越权、旧版本和事务失败回滚的后端与跨角色 E2E 全部通过。

### 5. 六类导入与安全回滚，再做总验收（Task 13–19）
