# 周通报与处分文书共用 Word 编辑器方案（审查稿）

本轮交付设计。通过审查后按本文切片编码。目标是让经办人在正文中排好文字、字段和表格，再从选定的通报版本或已确定处分生成 Word。编辑器配置控制呈现，业务记录提供事实。首版固定八类通报表的列、统计、分组和合并规则，自定义表结构留待后续。

## 业务前置：先确定累计项，再配置处分模板，最后出文

处分规则中已经确定的累计项是处分模板的配置入口。先选择累计项，再创建、编辑并保存对应模板；只有已生效的模板版本才进入出文选择列表。草稿可用虚构样例预览。某累计项尚无可用模板时，归档仍可查看，出文入口提示“该累计项尚无可用模板”；有配置权限的经办人可进入该项配置。

正式出文从已确定处分记录出发。服务端使用事项保存的规则版本、累计项稳定键和处分档位代码匹配模板。累计项所在规则已发布，即视为累计项及该版档位已确定。周通报表仍取所选通报版本的数据。

**数据与兼容。** 现有迁移 081 的有效绑定主键是规则版本和累计项；出文查询也只匹配这两列。目前的确认日期字段直接读取审批时间。本次实现需要追加迁移，改为按“规则版本＋累计项＋档位”唯一绑定，并校验档位属于该累计项。列表、编辑、保存、发布沿用和归档生成统一使用这组标识；保存时按目标档检查版本冲突。旧累计项模板保留版本与历史关联，建议在现有各档提供为可复用来源，由维护者逐档确认。新文书确认日期使用独立字段；旧模板中引用审批时间的字段保持原义，编辑时可显式替换。

**验收例。** 同一累计项 A 档配置横版，B 档复用 A 后改为竖版并修改正文。分别从 A、B 事项生成并核对实际 Word 的方向、文字、档位和条款。此后修改 A，B 的生效版本与已生成文书均应保持可追溯。无目标档模板时提示具体累计项与档位；不能临时借用相邻档出文。同时覆盖仅有模板编辑权、仅有出文权且可查看目标、预览后撤权、改日期后重新预览、重试不改变文号及日期。

### 已确认的换版规则：逐项判断模板是否沿用

在新规则发布生效时比较前后两版的累计项。编辑、保存规则草稿期间，现行模板继续可用。

- **累计项未变**：稳定累计项键和对应的日常检查配置均未改变，按仍存在的相同档位代码逐一沿用有效模板；新增档位待配置、移除档位保留历史。将匹配到的模板版本关联至新规则，保留原版式，无需复制模板或逐项重新确认。比较检查成员时按稳定检查类型标识匹配，忽略展示排序和换版产生的数据库行 ID。
- **累计项被撤销、拆分或合并**：旧项模板退出新规则的可用目录。即使新项沿用旧名称或键，也要核对检查成员；发生重新归组的累计项须重新配置模板，待模板生效后才能出文。未受此次归组影响的累计项继续沿用。
- **历史追溯**：保留旧累计项、旧模板及历史出文之间的关联，已生成文件仍可追溯到当时的版本。建议模板适用关系随规则发布事务一次更新，发布失败时维持原可用目录。

**验收例**：旧版“卫生累计”合并宿舍卫生与公共宿舍卫生，另有独立的“晚自习累计”。新版草稿把卫生拆成两项时，现行卫生模板仍可用。新版发布后，两项卫生分别显示“待配置模板”，均不能用旧卫生模板出文；晚自习继续使用原模板版本和版式。仅修改两项的显示顺序再发布，模板继续可用。

样件用 Word 主题色 accent2（保存的 RGB 为 EE822F）标出变量。下表按语义合并重复位置和被 Word 拆开的文字片段，只保留文书结构。表内“待补”表示配置设计，不能据此判定当前已支持生成。

|---|---|---|---|
| 文件抬头的发文字号 | 发文字号（整项） | 模板插入文号字段，文号含前缀、年度和序号；展示时避免重复前后缀 | TODO：编号规则与正式取值来源暂定 |
| 标题、正文身份段、决定句 | 学生姓名、处分档位名称 | 同一已确定事项的学生及档位快照；姓名引用三处，档位引用两处。姓名中的排版留白不进入姓名数据 | 已有姓名、档位字段 |

| 正文违纪事实 | 事实数量、违纪事实名称 | 数量与事实名称必须描述同一事实。可为累计项配置文书用语；仅当累计口径确为原始发生次数时输出“次数”，否则按来源明细统计或使用累计值及其单位表述 | 已有折算后的累计值和单位；它们不足以证明“发生 N 次”。累计项名称也未必适合作为事实名称 |
| 正文处分依据 | 依据文件文号、章条款定位 | 依据应来自命中档位所用的规则版本。样件将文件名、文号前缀和“号”等保留为普通文字，彩色部分覆盖文号年份与序号、完整章条款定位。可将完整依据文号设为一个字段，模板相应移除固定前后缀 | 已有自由文本“依据条款”；尚无独立依据文号。条款全文与章条款定位需要明确区分 |

模板作者决定字段位置、普通文字、标点、字号和对齐；出文人员不逐项重填学生和案件数据。首版样件中的主送称谓、学院与办公室名称、教育提醒段等未标色内容可作为模板正文维护。需要强调的是，依据文号属于被引用的制度，发文字号属于本次决定书，两者分别配置。配置预览使用合成样例；正式出文遇到模板引用的必填快照缺失时，应指出具体字段。样件标记色仅用于识别变量，正式文件沿用模板的正文格式。

发文字号与日期的配置见上述 11 月 23 日审查稿。验收需覆盖跨年、重复姓名字段一致、班级后缀不重复、累计折算、缺少性别或依据文号、两种日期不同以及历史文书重出。

**实现契约。** 共享编辑器根据文档用途装配“通用＋周通报”或“通用＋处分”的插入目录。节点使用分域稳定键（例如 common.generatedDate、report.reportDate、discipline.decidedAt），另行声明行内或块级、数据来源和解析器。旧周通报变量按原语义映射。模板维护阶段只开放与用途及所选累计项相容的字段，并提供明确标注的样例。处分侧后续接入其他来源时，应逐项声明它和事项的关联键、版本依据及访问范围，经过审核后加入白名单。保存、预览、正式生成三个接口均校验文档用途、节点和来源；覆盖从另一种模板粘贴节点和直接提交伪造字段的情况。

### 通用表格

通报和处分模板都可插入空白表格。选择初始行列数后，可在当前单元格增删行列、修改对齐，或设置全部、仅上下及无边框。“尺寸与边线”按表宽百分比设置当前列宽、按磅设置最小行高（0 为自动），可逐边设为透明。相邻格共享的边线同步处理，DOCX 保留列宽比例、最小行高及单元格边框。单元格可输入文字、设置字号、插入本业务允许的字段，Tab 与 Shift+Tab 在单元格之间移动。印发栏由一行两列、仅上下边框及右格右对齐组合得到。既有印发栏按这一配置打开，历史版本保持原样。固定通报统计表继续引用业务数据。编辑行为参考 [Tiptap Table](https://tiptap.dev/docs/editor/extensions/nodes/table) 与 [ProseMirror Tables](https://github.com/ProseMirror/prosemirror-tables)。

## 一、编辑器和文件如何接通
### 归档出文 API 契约（feat-0.4）

- `POST /api/v1/discipline/archive/:id/document/preview` 接收 `templateId`、`decisionDate`、`issueDate` 和 `issueNumber`。返回 JSON，包含正文 `document`、选中版本 `templateId`、可用版本 `editions`、实际字段 `fields` 和缺失项 `missing`。
- `POST /api/v1/discipline/archive/:id/document` 使用同一请求结构，核验权限、事项及适用版本，校验文件成功后写入审计并返回 DOCX。确认日期与印发日期分别设置，文号暂由经办人填写，自动编号规则待定。
- 通报版式预览和预览下载统一使用示例学期、第 9 周和 2025-06-01。实际通报的文件日期仍按周次维护。

沿用项目 Tiptap 3、现有通用工具和 Go DOCX 输出。周通报与处分配置使用同一个编辑组件，各自传入可用内容目录、样例数据和保存回调。保留项目已支持的字体、字号、段落样式、对齐等能力，盘点既有菜单、快捷键、签发落款与往返保存行为并作为回归基线。

现有引言编辑器已经有行内原子节点 templateVariable，但保存转换只识别少数通报变量，未知变量还可能落为学期名称。先抽出通用工具和转换器，再引入带格式版本的文档结构：段落内允许文本和字段，文档顶层允许段落、标题和固定业务表。字段保存稳定 key，表保存检查类型 code；文档保存节点顺序和受支持的格式。服务端按模板用途校验节点、属性、嵌套、长度与数量，拒绝未知 key 和越界格式，前端保留未保存输入。正文不执行脚本或任意表达式。[引言编辑器](../../web/src/features/reporting/ui/ReportIntroductionEditor.tsx) · [落款编辑器](../../web/src/features/reporting/ui/ReportFooterEditor.tsx)

Tiptap Node View 负责编辑态表块；Go 将模板和业务快照解析成有序的段落、文字片段与表格，再分别交给预览和 DOCX 渲染。每次预览或导出显式传入模板版本与业务版本，权限、可用状态和字段值在服务端读取。浏览器预览核对内容、顺序与格式，精确分页以下载文件在 Word 中的排版为准。[Tiptap React Node View 示例](https://tiptap.dev/docs/editor/extensions/custom-extensions/node-views/react) · [Word 内容控件](https://learn.microsoft.com/en-us/office/client-developer/word/content-controls-in-word)

## 二、插入目录与 Word 排版契约

| 内容 | 首批目录和数据来源 | 光标与编辑规则 | DOCX 规则 |

| 处分依据条款 | 事项保存的命中条款快照 | 行内字段，可写成“依据〔条款〕，决定……”；较长内容也可由作者另起段落放置 | 原文保留，多行条款在段内换行；不把新规则的措辞套用到旧处分 |
| 固定通报表 | 到课率、无机课堂、晚自习、早读、教室卫生、宿舍卫生、公共宿舍卫生、晚归；实现以检查目录的稳定代码关联现有输出器 | 块级原子节点，独占文档流位置。在段中插入时从光标拆成前段、表、后段；支持整块移动、撤销、删除和键盘离开 | 输出原生 Word 表格，前后文字各自成段。保留列名、表头重复、合并和分页规则。插表只产生表体；编辑态名称、外置表题和自动续标题均不随表输出 |

示例：教师输入“依据〔处分依据条款〕，给予〔处分档位〕处分。”，生成时整句仍是一段。教师在“检查结果如下。整改要求见下文。”两句之间插表，生成顺序应为第一句、表格、第二句。宿舍表如需分组识别，应保留业务分组信息；外置组标题与表内分组行须按真实样张逐项核对，不能因移除外置标题丢失组名。

历史模板继续按原版本渲染。编辑旧模板时提供转换预览，把原先自动生成的标题显式转换成可编辑标题段，再放入对应表块；新格式只按节点顺序输出。用现有 Word 样张对照首页、续页、卫生分组和签发区。缺失必填快照字段时明确指出字段并阻止出文；合法空表与读取失败分别呈现。建议合法空表仍保留已配置的表头，供审查确认。[Word 输出器](../../server/internal/reportoutput/render.go) · [Word 样式](../../server/internal/reportoutput/word_layout.go)

**印发信息的横线。** 样件在文字附近放置两条浮动横线。模板改用跟随文字段落的原生 Word 边框：提供“上下单线”（文字上、下各一条）和“下方双线”（文字下方两条），可清除。换行或横竖版切换时随段落宽度排版，字段仍可在文字中插入；保存、重开和 DOCX 应保留该格式。更改此版式属于有效二次编辑。

## 三、页面与交互参照

- **处分配置 → 处分文件配置**。与处分规则配置同级。先选择已确定的累计项，再逐档展示模板与适用版本。模板列表沿用项目的 ProTable 查询、工具栏和历史版本入口。进入编辑后复用周通报编辑器的工具栏与纸面，增加“插入字段”；周通报编辑场景另显示“插入通报表”。菜单展示中文名和样例值，键盘选择后回到原光标位置。
- **编辑与预览**。编辑态用有文字标签的字段和只读表块表现可插入内容；预览态隐藏选择框、块操作和字段标签。模板维护者用虚构样例预览，避免因编辑权限读到学生数据。窄屏把插入菜单收起、表格滚动限制在表块内部；支持键盘插入、整块删除、撤销和返回正文。
- **处分归档 → 生成文书**。从具体已确定记录发起，匹配该累计项与档位的模板，确认文书日期、预览实际内容、下载 Word。作废记录保留历史追溯；正式出文前再检查当前记录状态。失败时保留模板选择，重试沿用同一请求标识。记录事项、规则与模板版本、经办人、生成时间；成功以文件完成校验为准，下载/打印不改变处分审批状态。

## 五、交付顺序和验收

1. **编辑器切片**：抽取通用工具栏，接通一张到课率表和四个现有行内变量。验证中间插入、表后继续输入、撤销、移动、粘贴、保存重开、旧模板转换和样例预览。
2. **通报 Word 切片**：再覆盖宿舍分组和跨页，然后扩至八类。解包 DOCX 核对正文段落与表格顺序、自拟标题只出现一次、列名与数据不丢失，并用 Word 实际打开长表检查分页。
3. **处分模板与出文切片**：同步交付两项权限、模板版本、归档预览/导出和审计。以同一份模板生成两位虚构学生的文件，核对字段不会串人；用旧规则处分验证依据快照，验证必填缺失、版本冲突、重复请求、撤权和作废拒绝。
4. **来源和前置条件回归**：覆盖累计项未确定、只有草稿、模板错项、规则版本不匹配、事项已作废和历史快照缺失；验证通报模板拒绝处分专属字段、处分模板拒绝通报表。用历史通报和历史处分分别验证“生成日期”“通报日期”“确认日期”各取其源。
5. **权限与 GUI 验收**：一次性 PostgreSQL 和真实 API 覆盖仅编辑、仅出文且可查看目标、仅归档 Excel 导出、两权齐全、越范围和弹窗内撤权。Midscene 慢速录制“正文中间插表→自拟标题→预览→下载”及“配置处分模板→归档选记录→实际出文”，附生成的合成数据 DOCX。页面呈现与文件内容分别验收。

**本次请审查三个具体决定**：处分字段首批清单是否够用；合法空表是否保留表头；两个新动作各自默认分配给哪些部门和岗位。文号编排、送达、批量文件包与自定义表列均留待单独确定。

## 补充：页面方向、分页与分节（周通报及处分文书共用）

Word 以节管理纸张方向。“分页”让后续内容从下一页开始并沿用本节设置；“下一页分节”同时建立可独立设置方向的新节。开源 python-docx 的横版示例设置节方向并交换纸张宽高。Tiptap 的自定义节点可以表达文档中的显式边界；编辑画布上的分隔线只是该节点的编辑态呈现。项目 Go 导出器已有竖版引言、横版表格、分页和节属性 XML，新模板复用这些能力，改由模板指定边界。[Microsoft Word 分节说明](https://support.microsoft.com/en-us/word/use-section-breaks-to-change-the-layout-or-formatting-in-one-section-of-your-word-document) · [python-docx 分节示例](https://python-docx.readthedocs.io/en/latest/user/sections.html) · [Tiptap 自定义节点](https://tiptap.dev/docs/editor/extensions/custom-extensions/create-new/node) · [现有导出器](../../server/internal/reportoutput/render.go)

- **页面设置**：默认 A4 竖版。工具栏显示“页面方向：纵向/横向”，作用于光标所在节；单节时作用于全文。插入“下一页分节符”时新节继承原方向，可随后改为横向。首版只提供下一页分节。
- **保存契约**：v2 文档首节方向由顶层 orientation 保存（缺省 portrait）；顶层原子节点 pageBreak 表示普通分页，sectionBreak.attrs.orientation 表示下一节方向。禁止放到表格内部或字段内部。段中插入先拆段；可键盘选择、删除、撤销。删除分节符合并两节时统一沿用前节方向，操作提示明确说明。
- **跨端节点示例**：段内日期为 `{"type":"templateField","attrs":{"key":"common.generatedDate"}}`，通报表为 `{"type":"reportTable","attrs":{"key":"<检查类型稳定代码>"}}`，二者分别放在段落和文档的 `content` 中。例如先写竖版说明、插入横版通报表、最后写竖版落款，保存时依次是说明段、`sectionBreak(landscape)`、表节点、`sectionBreak(portrait)`、落款段。普通分页使用无属性的 `pageBreak`。模板中只保存字段引用，生成值由所选业务快照或明确的公共来源提供。
- **预览与导出**：编辑态用细线和中文名称区分两种边界；预览体现纸张宽高、边界和表格可用宽度，隐藏编辑控件。显式分页写 Word 分页符；下一页分节由节属性独立实现，避免附加一次分页导致空白页。中间节属性写在结束段，末节属性写在文档体结尾，逐节保留页边距、页眉页脚及连续页码。未转换的旧模板沿用原布局。
- **验收**：用同一模板验证“竖版说明 → 横版通报表跨页 → 竖版落款”，以及“同一竖版节内手动分页”；保存重开、撤销删除、无表的横版处分文书都要覆盖。解包核对节数、方向、宽高、分页符位置；再打开 DOCX 检查跨页表头、落款所在页及意外空白页。
