# 日常检查部门隔离：修正范围与回归审查稿

状态：原记录维护隔离已在工作区实现，已通过下述隔离回归。八类页面逐角色及目标环境验收仍待完成。

## 一、已明确的规则

| 业务问题 | 判定依据 |
|---|---|
| 谁能查看原记录？ | 沿用有效查看权限。多个部门共同负责到课率时，允许出现“能看到其他部门记录，只能查看”的情况。待审批次另按批次权限读取。 |
| 谁能维护部门草稿？ | 委员默认凭本部门有效录入权维护本人记录。部长、副部长默认凭本部门管理权维护本部门记录。实现检查实际授权；记录的部门、检查类型、动作、有效期和操作范围须在同一授权来源内满足。其他部门即使管理同类型、同年级，也不能据此维护这条记录。 |
| 谁能维护普通管理员创建的记录？ | 创建管理员本人凭有效权限维护，超管可以维护。其他普通管理员及部门成员均不能接管，包括接收审核的部门。手工与 Excel 录入遵循同一原则。创建身份和来源应可追溯。 |
| 提交到哪里？ | 保留已有通道。管理员在提交时可以选择有权使用的负责部门或管理员通道。多部门成员本人记录沿用已有选定所属部门的提交规则。通道选择不改写创建来源。 |
| 谁能审核？ | 按提交批次所属通道和有效审核权判断。部门批次由获该部门审核授权、覆盖整批的人员处理。确认、退回作用于批次。退回后的原记录修正仍按维护权检查，重提沿用原批次及修订历史。 |
| 超管能做什么？ | 可跨部门维护及处理批次，仍须遵守状态机、版本、锁定、定稿保护及审计。 |
| 年级如何参与？ | 对限制为 26 级的管理授权，先核对部门，再检查年级、专业、班级范围。多个责任班级须全部覆盖。24 级和 26 级的外部门记录都应拒绝维护。 |

普通管理员处理**部门成员创建的记录**按现有显式业务授权核对。本稿不新增“全院管理”授权项，也不推定所有管理员已有全院写权。复核实际授权配置能表达的部门及范围；若现有授权没有明确部门语义，列入待确认，不自动扩权。

既有规则见[管理员提交通道](2026-11-10-admin-submission-routing.md)、[批次审核归属](2026-11-14-department-submission-review-scope.md)。

## 二、实施时要改和要保护的地方

1. **原记录维护鉴权。** 从数据库取创建来源、创建人、原归属和状态，统一用于详情能力标记、更新、单删、批删。授权来源部门要和记录归属匹配。检查工程中八类业务的通用及专用入口。先核实历史记录是否足以区分管理员创建，不用当前角色或后续提交部门倒推历史身份。
2. **列表、详情和操作入口。** 保留已授权的查看能力。逐行编辑、删除、批量勾选及抽屉保存与后端判定一致。校验保存前后的数据范围，防止通过改班级或部门改变归属。对于可见但无写权的记录给出一致、可理解的权限提示。
3. **导入与批量操作。** 导入确认逐条检查目标及范围。导入记录与手工记录遵循相同维护边界。回滚校验整个批次的归属、权限、版本、提交和锁定状态；任意一条不满足，整批不得部分写入。
4. **保护已有流程。** 将提交候选、实际提交、审核、退回和重提逐项复验。不要直接收紧共享 SQL 以致管理员双通道或多部门本人提交失效。查看原记录和查看待审批次分别验证。
5. **可追溯性。** 通过后复核实际操作者、原创建人、来源部门、提交去向和批次修订；失败时核对版本、记录及关联批次无意外变化。

## 三、人工与自动化回归清单

使用一次性 PostgreSQL、独立 Bucket、真实 API 和虚构账号。在同学期、同周、同检查类型下准备学习部 A、大一年级部 B、另一共同负责部门 C。准备 A 委员甲、乙，A 部长，限 26 级的 B 部长，C 管理成员，A/B 双部门老师，普通管理员管甲、管乙和超管。A 甲分别以手工、Excel 创建 24 级和 26 级记录；B、C 各建本部门对照草稿。写操作使用独立草稿，避免前一用例改变后一用例的状态。

| 编号 | 操作 | 验收结果 |
|---|---|---|
| 01 | A、B、C 成员分别在本部门创建；单部门成员选其他部门创建 | 本部门在有效录入范围内成功；跨部门创建被拒，数据库中无新记录。 |
| 02 | A 甲编辑、删除自己的两份独立草稿；只有录入权的 A 乙操作甲的记录 | 甲在有效范围内成功；乙可按授权查看，不能编辑或删除。 |
| 03 | A 部长管理甲、乙的记录；再将管理范围限定为 26 级 | 本部门范围内可维护；限 26 级后，24 级不可维护，26 级仍可维护。 |
| 04 | B 部长和 C 管理成员查看并尝试维护 A 的 24、26 级草稿，分别覆盖手工与导入 | 授权查看正常，两年级均不可编辑、删除。B 部长仍可维护本部门 26 级对照草稿。 |
| 05 | 批删包含 B 自有记录与 A 的一条记录；再单独删除有权记录 | 混合批次整体拒绝、所有行版本不变；合法单删成功。 |
| 06 | 两个部门分别导入；对本部门及外部门的导入批次尝试回滚；本部门批次中含已锁记录 | 仅完全符合权限和状态的批次可回滚。跨部门或含锁定行时，批次及原记录不变。 |
| 07 | A/B 双部门老师在 A 有录入权，在 B 有管理权，尝试编辑 A 其他人的记录 | 不能借用 B 的管理权。对自己创建的草稿，原有合法提交通道仍可用。 |
| 08 | A 提交自己的记录；B、C 打开候选、批次列表和审核入口 | B、C 不能代交 A 的草稿，不能审核 A 的批次。具备 A 审核权且覆盖整批的账号能正常确认或退回。 |
| 09 | 管甲建两份草稿，一份提交学习部，一份走管理员通道 | 两个合法去向均能提交；记录保留管甲创建来源，各批次保存实际通道。 |
| 10 | 管乙与学习部部长分别尝试维护管甲草稿；学习部审核人退回管甲提交的批次，管甲修正并重提 | 管乙、部长均无法接管原记录；授权审核人可退回，管甲可按状态修正、重提，修订历史完整。 |
| 11 | 普通管理员仅有查看权、只有某部门管理权、有审核权无管理权三组对照 | 查看、原记录维护、批次审核分别符合显式授权；管理权不自动带来审核权。覆盖管理员他人草稿时仍按第 10 项拒绝。 |
| 12 | 超管维护跨部门及管甲草稿，再尝试直接修改锁定记录或使用旧版本保存 | 合法草稿操作有审计；锁定或版本冲突明确拒绝，保存原值。 |
| 13 | 审核人只有部分责任班级权限；撤销写权后从已打开的编辑抽屉保存 | 整批审核拒绝；过期页面保存被后端拒绝，可见权限反馈，原记录不变。 |

用例 02–06 同时核验 GUI 和服务端行为。成功用例检查数据库实际改动；拒绝用例记录 HTTP 状态、稳定业务码和操作前后数据。八类页面逐类核对读写入口；至少对学生记录、含多个责任班级的记录及 Excel 回滚执行真实写入回归。普通成员、普通管理员、超管的结果分别报告。
