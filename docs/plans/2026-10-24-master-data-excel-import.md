# 基础数据 Excel 新增导入方案与实现记录

## 范围

本期在基础数据管理页增加 Excel 批量新增。仅支持新增，不提供更新、覆盖、停用记录重启用、批次撤回或批量删除。课程排课字段和课程数据均不进入本期，课程是否适合批量维护后续结合现有课程与排课设计单独评估。

支持 11 类基础数据：院系、年级、专业、教职工、班级、宿舍区、宿舍楼、宿舍、教学楼、教室、学生。导入生成的数据均启用；系统生成记录 UUID、编码之外的技术字段、关联 ID 和审计字段。模板中的标题、字段编码、字段顺序、工作表名称和版本必须与当前分类模板完全一致。

## 每类模板字段与格式

通用要求：使用当前分类下载的 `.xlsx` 模板；第 4 行逐列说明字段类型、格式和校验要求，第 5 行逐列给出对应示例值。说明行和示例行仅供参考且由服务端自动忽略，实际数据从第 6 行开始填写。示例使用一组连贯的虚构场景，例如院系“计算机科学与工程学院”、年级“2026”、专业“软件工程”、班级“2026级软件工程一班”和宿舍“4 区/1栋/001”；它们用于帮助理解字段关系，导入时须替换为系统中已启用的实际关联数据。保留工作表、隐藏元数据、表头和字段顺序；所有业务值按文本输入，不能放公式。字段值会去除首尾空格；长度按 Unicode 字符数计算。每个文件最多 1000 条数据。业务编码和学号按系统规则转大写；含数字标识、房间号和电话建议将 Excel 单元格设置为“文本”，以免 Excel 自动去掉前导零或改为科学计数法。包含格式说明行和示例行的新模板版本为 4，旧模板需重新下载。

## 交互和数据规则

1. 用户在基础数据分类进入“导入 Excel”，先查看服务端返回的当前分类字段格式并下载对应模板；课程分类没有导入入口。
2. 上传 `.xlsx` 后，服务端在私有对象存储保存源文件，先校验扩展名、签名、ZIP/OOXML 安全边界、模板代码/版本、工作表、隐藏元数据、字段编码、标题顺序、公式和最大行数，再解析业务行。
3. 服务端按字段规格逐行校验必填、长度、年份/整数格式、字典、已启用关联、文件内重复及数据库中已存在的唯一业务键。已停用记录仍占用唯一业务键，因此不能通过导入创建同一键的新记录。
4. 预览行和校验结果写入批次表，批次绑定源文件和创建账号。前端显示行号、字段值、有效/无效状态和错误原因。只要任一行错误，整批不能确认，用户需修正源文件后重新上传。
5. 确认请求只提交批次 ID、预览版本和幂等键。服务端按创建人读取批次，在 PostgreSQL 事务中锁定批次和当前引用/字典选项、复核引用仍启用、插入全部新记录、主数据变更历史、记录级审计及批次确认审计，最后更新批次状态。任一插入、唯一约束或审计失败整笔回滚。
6. 确认成功的同一幂等键重复请求返回原成功结果；其他幂等键无法重复确认。批次预览只有创建人可读取；所有接口均受 `MASTER_DATA_MANAGE` 后端权限控制。

## 接口与持久化

- `GET /api/v1/admin/master-data/:kind/import-spec`：取分类字段和格式说明。
- `GET /api/v1/admin/master-data/:kind/import-template`：下载当前分类 XLSX 模板，响应使用 `Cache-Control: no-store`，避免跨版本复用旧模板。
- `POST /api/v1/admin/master-data/:kind/imports`：上传并解析，返回持久化预览。
- `GET /api/v1/admin/master-data/:kind/imports/:batchID`：创建人读取预览批次。
- `POST /api/v1/admin/master-data/:kind/imports/:batchID/confirm`：使用 `Idempotency-Key` 和预览版本原子确认。
- 迁移 `022_master_data_import_batches.sql` 只追加导入批次表；源文件仍由现有私有对象存储和文件审计能力管理。迁移 `024_master_data_import_template_versions.sql` 将批次模板版本约束从固定值 1 改为正整数，支持后续模板迭代且保留历史批次；不得改写已应用的 022。

导入批次不提供回滚或删除入口。未与批次成功关联的上传源文件沿用既有补偿清理逻辑。源文件内容和预览行可能含个人信息，只能通过受权限保护的导入 API 读取；日志不记录单元格内容。
