# 管理基础平台设计

## 目标

在现有认证骨架上交付可由超级管理员直接操作的基础平台：系统管理员账号、注册审核、部门与角色、七类检查类型及部门业务映射、学年学期周次人工配置。

## 核心决策

- 登录凭据统一为 `login_name`。普通用户注册时登录名等于学号；系统账号 `admin` 不要求学号。
- `admin` 由启动配置幂等初始化，初始密码只从环境变量读取，首次登录必须修改密码。
- 普通注册账号初始状态为 `PENDING`，审核前不得创建或续期会话。
- 系统初始允许没有学年、学期和周次；此时管理后台可用，业务入口显示明确的未配置提示。
- 部门、组织角色、检查类型是有业务关系的独立实体，不作为普通字典项。
- 内置四个部门、四个组织角色和七个检查类型；映射由超级管理员维护。
- 学期周次日期范围不得重叠，当前周由服务端按日期计算。
- 学年由起始年份选择并自动生成下一年份及规范名称；学期固定为上、下学期，默认日期按 9 月至次年 8 月校历生成且可人工调整。

## 模块与调用方向

- `auth`：账号、登录、注册、审核、改密、会话与超级管理员鉴权。
- `organization`：部门、组织角色、用户部门角色分配、部门检查权限映射。
- `inspection`：检查类型查询与配置。
- `academic`：学年、学期、周次维护与当前周匹配。
- `httpapi`：仅负责 HTTP 输入输出和身份/超级管理员守卫。
- `store`：PostgreSQL 仓储，负责把数据范围和唯一约束下推数据库。

前端继续采用 `app → pages → features/entities → shared` 依赖方向。管理页使用统一侧栏布局；服务端数据经 API client 和 TanStack Query 管理，页面不直接调用 `fetch`。

## 安全与失败处理

- 不提供默认管理员密码，不把密码写入迁移、日志或响应。
- `admin` 初始化是幂等的，已有账号不会被启动配置覆盖。
- 待审核、已驳回、已禁用账号统一拒绝登录，避免泄露账号状态。
- 修改密码后撤销该账号全部刷新会话；首次改密成功后才解除管理页面限制。
- 所有管理 API 在后端验证超级管理员身份，前端菜单显隐不作为安全边界。
- 删除配置优先使用禁用；已经被引用的部门、角色、检查类型和学期周次不物理删除。

## 初始数据

- 部门：学生会办公室、学习部、宿管部、体育部。
- 组织角色：主席团成员、部门部长、部门副部长、部门委员。
- 检查类型：到课率、无机课堂、教室卫生、早锻炼/早签、宿舍卫生、晚归、公共宿舍卫生。
- 默认映射：学习部负责前三项，体育部负责早锻炼/早签，宿管部负责宿舍卫生、晚归、公共宿舍卫生；办公室拥有查看、汇总和通报协作范围。

## 前端页面

- `/change-password`：首次修改密码。
- `/admin/registrations`：注册申请审核。
- `/admin/users`：用户、部门和组织角色配置。
- `/admin/organization`：部门与检查类型映射。
- `/admin/academic`：学年、学期和周次配置。

视觉沿用学校蓝和现有 Ant Design 体系，采用清晰、克制的行政管理界面；重点保证状态提示、空数据引导、表格键盘操作、表单标签和危险操作确认。

## 验证

- 后端覆盖：管理员初始化、待审核登录拒绝、审核状态机、首次改密、超级管理员守卫、映射维护、周次重叠和当前周匹配。
- 前端覆盖：账号登录字段、首次改密路由、管理菜单权限、空学期提示、注册审核和配置表单。
- 交付前运行后端 `gofmt`、`go vet ./...`、`go test ./...`，前端 `pnpm lint`、`pnpm test`、`pnpm build`，并验证 Compose 配置。
