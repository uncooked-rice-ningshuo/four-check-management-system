# 文件恢复失败与并发保护（2026-10-04）

真实PG/MinIO交错复现：上传在更新AVAILABLE或FAILED前，另一恢复服务已成功把PENDING对象恢复为AVAILABLE；原上传状态更新失败后仍直接删除对象，造成已恢复文件丢失。两路径先红后绿，现状态写入失败只返回错误，保留对象和当前元数据；只有成功落库FAILED后才可清理。

PENDING恢复现先校验元数据大小及对象报告大小，再以“声明字节数+1”限制读取。超出配置上限记录FILE_TOO_LARGE，不读取内容；长度不符记录完整性失败。测试原异常流读取1MiB，声明3字节的修复后最多读取4字节；超限元数据零读取。

继续核验暂时失败：原Open/流错误也会落FAILED并删除。真实MinIO访问拒绝、真实对象读取到512字节后注入中断两场景先红，现保留PENDING与对象，RecordFileRecoveryDeferred将更新时间和FILE_RECOVERY_DEFERRED审计同事务提交，让其稍后重试。确定缺失、超限、长度不符才进入FAILED补偿。取消context导致延期写入失败时也不删对象。
