# 日常检查调整实施方案

> 状态：需求已梳理，待实施。方案依据[飞书调整记录](https://acna9bso0eml.feishu.cn/wiki/BS2AwSXbiiAE3OkGqpUcB2ysnEe)及 2026-11-01 对话澄清。当前没有改动业务代码、数据库或运行环境。

## 1. 目标与范围

本轮调整覆盖系统现有八类检查：到课率、无机课堂、早锻炼/早签、宿舍卫生、晚归、晚自习、教室卫生、公共宿舍卫生。教室卫生和公共宿舍卫生此前在 PRD 中暂缓；本轮明确恢复开发和验收，需同步更新 PRD 与技术方案。实现时仍由检查类型配置决定负责部门，不在代码中写死部门映射。

本方案覆盖记录字段和粒度、重复校验、八类列表筛选、早签计划日期配置、管理员录入归属与 Excel 导入契约。出勤率公式和通报比率不在本轮范围。

## 2. 已确认的业务规则

### 2.1 卫生记录改为逐人记录

宿舍卫生、教室卫生、公共宿舍卫生均按“一名负责学生一条记录”处理。新增/编辑字段如下：

| 类型 | 必填字段 | 情况说明 | 移除字段 |
| --- | --- | --- | --- |
| 宿舍卫生 | 班级、寝室、负责学生、检查日期、结果 | 不合格时必填自由文本；下方展示常用说明，可填入后继续修改 | 检查时点公式、检查时间、不合格原因代码 |
| 教室卫生 | 班级、教室、负责学生、检查日期、结果 | 不合格时必填自由文本；下方展示常用说明，可填入后继续修改 | 检查时点方式、检查时间、不合格原因代码 |
| 公共宿舍卫生 | 班级、负责寝室、负责学生、检查日期、结果 | 不合格时必填自由文本；下方展示常用说明，可填入后继续修改 | 公共区域、检查时点方式、检查时间、不合格原因代码 |

公共宿舍卫生中的“寝室”只表示责任寝室，不代表实际检查位置。此类型不再记录公共区域。前端下拉项必须来自现有基础数据；服务端验证所选学生、班级、寝室/教室之间的有效关系，并保存记录所需的名称快照。

新记录不再收集旧的原因代码和检查时点字段；情况说明是唯一的不合格说明字段，非不合格结果时可选。常用情况说明使用与卫生类型对应的字典短语库，直接展示在文本框下方，不做下拉框，也不作为枚举或必选项。点击短语后填入文本框：文本为空时直接填入，已有内容时追加到末尾并换行；填入后可任意编辑，保存的是最终自由文本。没有选择字典短语时也可直接填写。

字典只提供录入起稿，不记录为原因代码，不限制用户最终文本，也不参与统计分类。管理端通过现有字典维护能力维护条目；卫生三类分别加载对应短语。当前调整记录未列出具体短语文本，实施时使用已维护的字典内容，不臆造词条。字典加载失败不能阻断手工输入。

旧记录、审计数据和已冻结通报快照不回写、不删除；历史详情可继续展示旧字段，新建和编辑契约按新规则执行。卫生检查不允许同一检查对象、责任学生和日期复查。

### 2.2 晚自习与晚归改为日期级事件

- 晚自习：教室改为选填；删除检查时间；日期必填。既有第 9–10 节和两学时的服务端固定规则继续有效。
- 晚归：删除晚归时间，保留晚归日期。
- 两类事件均按学生、班级、日期唯一；同一学生同一天最多一条。

### 2.3 重复记录键

重复校验必须在手工新增/编辑、Excel 预览、确认入库、批内重复检查和数据库并发保护中一致执行。学期、周次和检查类型仍作为记录上下文参与隔离。

| 检查类型 | 同一范围内的业务重复键 |
| --- | --- |
| 到课率 | 班级、学生、检查日期、规范化开始节次、结束节次；不含课程。同一时段不同课程仍视为重复，需修正已有记录。 |
| 教室卫生 | 班级、教室、负责学生、检查日期 |
| 早锻炼/早签、晚自习 | 班级、学生、检查日期 |
| 晚归 | 班级、学生、晚归日期 |
| 宿舍卫生、公共宿舍卫生 | 班级、负责学生、责任寝室、检查日期 |

迁移前先用新规则盘点活动记录中的重复冲突。不得自动合并、删除或更改已确认、已锁定记录；如冲突存在，保留数据并由业务方决定如何处理，再决定唯一约束的启用方式。软删除记录的重录行为沿用现有有效记录规则。

### 2.4 早签周计划

早签/早自习沿用现有 `MORNING_ATTENDANCE` 检查类型，不新增检查类型。配置对象应表达“本周哪些日期安排早签”，而不只是总次数：默认勾选该周周一至周五的日期；体育部部长、副部长可逐日增加或取消安排。权限限定为修改早签计划，不自动授予其他校历、记录或检查类型管理权；服务端每次写入重新校验角色和权限并写审计。

Excel 模板不提供计划日期或次数列。计划由周配置产生，导入文件只提交缺勤事件。推荐由同一个服务端生效计划校验手工和导入记录：未修改时即使用默认工作日；如体育部修改了该周计划，后续两种来源都按修改后的日期校验，避免同一日期因来源不同而得到不同结论。计划配置用于后续校验；本轮不计算或展示出勤率，也不新增人数分母、应到/实到或缺勤率。

### 2.5 记录归属与管理员录入

录入人、数据归属和数据来源必须分开表达：`created_by` 是操作人，`department_id` 是业务归属，`source` 是手工或 Excel 来源。不能把管理员身份伪装成某个部门，也不能用“目标部门”代替录入人身份。

- 普通成员：继续自动归入账号主部门，不提供部门选择。
- 管理员代部门录入：仅在确实代表某部门时使用“业务归属部门”。若检查类型映射唯一则自动带出；多个可用部门时才要求选择，并在批次/录入上下文中选择一次。
- 管理员独立录入：不选择部门，单独标记为管理员归属/录入范围并保留实际操作者。它不能静默进入任意部门的提交与审核队列。列表、审核和通报来源应能与部门归属记录区分。

若现有 `department_id IS NULL` 的“校级”范围要承载管理员独立录入，需增加可区分新旧语义的归属类型或等价字段；不能仅把所有“校级”文案全局替换为“管理员”，也不能改写历史范围。实现前要明确管理员独立记录沿用哪一套审核授权，以及通报中显示为“管理员录入”还是独立的管理范围。

## 3. 按代码层次的修改点

### 3.1 文档与领域契约

- 更新 PRD 当前范围、三类卫生字段、晚自习/晚归日期规则、重复规则和管理员归属语义；删除两类卫生“暂缓”的旧结论，保留历史决策标记。
- 更新技术方案的数据模型、`department_id` 归属解释、早签计划和权限、导入/重复校验事务及报告快照边界。
- 更新统计需求说明：早签计划日期可用于校验；出勤率和应到/实到继续待后续规则确认。
- 为宿舍卫生、教室卫生、公共宿舍卫生各维护一个常用情况说明字典类型，字典条目的展示文本作为可编辑草稿；更新 `server/internal/inspection/catalog.json` 与领域模型，使八类字段、重复键和可用导入动作反映新规则。

### 3.2 数据库与后端 API

- 采用只追加迁移；为早签周计划和授权审计增加持久化字段/表及并发版本保护。
- 将卫生写入校验收敛为单个负责学生及对应班级；公共宿舍不再要求 area，责任寝室作为字段保存。
- 日期型晚归/晚自习写入日期事件，不伪造业务时间；旧时间数据留存。
- 更新重复键计算、数据库活动记录唯一保护、导入查重和确认时的二次校验。对到课率节次做规范化解析，避免等价表达绕过重复检查。
- 新增早签计划查询/更新 API；只允许指定的体育部部长、副部长修改计划，非法日期、越界周次和并发旧版本均明确失败。
- 复用现有字典读取与维护 API 提供三类卫生说明短语；服务端只校验情况说明的长度及“不合格时非空”，不得验证提交文本是否等于某个字典条目。
- 为八类列表补齐学期、周次、部门、年级、班级、姓名/学号关键词、数据状态、数据来源筛选。服务端先按有效权限过滤，再应用业务筛选；不得先查全量后内存过滤。
- 将管理员的“部门代录”和“独立录入”作为不同归属模式贯穿单条写入、导入批次、部门提交、审核和通报来源；不能只改下拉框文案。

### 3.3 页面与 Excel 导入

- 八类检查列表统一筛选交互和字段命名，保留各类型自己的业务列；部门留空仍表示查询全部有权范围。
- 重做三类卫生新增/编辑/详情字段和联动选项；不合格时显示并要求情况说明。文本框下方平铺显示可点击的常用短语按钮，不使用 Select/下拉菜单；点击后填入/追加到文本，后续可编辑，最终按普通情况说明保存。
- 说明短语字典为空或加载失败时，仍允许手工输入；维护字典条目后刷新即可显示新短语。保存和通报快照只保留最终文本，不把字典条目 ID 当作记录原因。
- 晚自习表单将教室设为可空并删除时间；晚归删除时间控件。记录详情和编辑回显覆盖旧记录兼容。
- 早签周配置页显示本周日期列表和默认状态；仅有专属权限的人可修改，保存后显示当前生效日程。
- Excel 模板及解析器按新字段调整；预览反馈新重复规则，确认阶段再次校验。公共宿舍卫生要补齐导入入口及完整导入动作。
- 当前后端模板按检查类型发布，不按部门分模板。本轮不改模板归属模型；用户报告的本地下载按钮问题单独作为运行环境/下载故障排查，不混入需求变更。

### 3.4 管理员录入及通报展示

- 列表和详情分别展示“录入人”“归属范围/部门”“数据来源”，不再用一个“目标部门”字段表达三者。
- 代部门录入沿用该部门的审核与通报归属；独立管理员录入走明确的独立审核授权，并在通报中明确来源，不能作为部门记录计数。
- 旧报告版本保持不可变。新报告快照冻结归属类型和展示名称，保证以后改名或组织映射变化不影响历史通报。

## 4. 实施阶段与依赖

1. **先同步需求文档并做只读预检**：更新 PRD、技术方案和本计划；盘点活动记录在新重复规则下的冲突；确认当前类型映射是否唯一及管理员独立录入的审核/通报授权。
2. **数据模型与后端契约**：只追加迁移，完成卫生逐人模型、日期事件、早签计划、归属模式、重复保护和八类筛选 API。
3. **页面和导入适配**：完成八类筛选、三类卫生表单、晚自习/晚归日期字段、早签计划配置及 Excel 预览/确认契约。
4. **工作流与通报来源**：验证部门代录按原部门流程审核，独立管理员记录按明确的管理范围处理；报告快照区分来源归属。
5. **隔离环境验收**：先在一次性 PostgreSQL 验迁移和活动冲突策略，再跑后端/前端检查及真实 API/浏览器流程；真实环境加载、模板发布和角色验收分开记录，不以本地通过代替部署验收。

## 5. 验收条件

- 八类列表均有统一筛选项；跨类型和未授权部门查询都由服务端正确限制。
- 三类卫生均可新增、编辑、查询和导入逐人记录；不合格无情况说明时拒绝；历史字段仍可安全读取。
- 三类卫生说明短语按类型展示为文本框下的直接填入按钮；选择后可改写，未选择短语也可输入并保存任意合规文本；字典不可用不阻断记录录入。
- 晚自习教室可空且节次服务端固定；晚归、晚自习按学生日期去重。
- 到课率跨课程同日同节次被识别为重复；卫生同对象同学生同日不能复查；手工、导入预览和确认结果一致，确认竞态有数据库保护。
- 早签默认日期正确，体育部部长/副部长可改，其他角色不能改；计划变化有审计；记录日期校验使用统一生效计划。
- 管理员代部门录入和独立录入的批次、审核、记录列表、权限及通报来源可区分；不出现误归属部门或把管理员记录伪装成部门提交。
- 不计算出勤率，不改历史定稿快照，不发生未授权的真实业务库迁移或部署。

## 6. 不在本轮范围

- 出勤率公式、在籍人数快照、应到/实到及零缺勤班级完成证明。
- Word/Excel 通报产物模板设计和生成；当前模板下载故障只做独立排查。
- 生产数据去重、历史数据合并/删除、旧定稿改写。
- 改变部门与检查类型映射、扩大管理员权限、把管理员独立记录并入某个部门。
- 未经单独确认的部署、提交或推送。
