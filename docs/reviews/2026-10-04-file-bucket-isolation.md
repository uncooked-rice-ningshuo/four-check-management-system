# 文件元数据 Bucket 隔离（2026-10-04）

准备恢复入口时确认：MinIO实例固定使用配置Bucket，Open/ReadVerified/Discard/Reconcile却没有核对元数据Bucket。真实双Bucket放入相同key和内容后，五条路径均先失败，证明会读取/删除错误Bucket或错误恢复元数据。

服务现在在对象访问前核对非空Bucket且与配置一致；不匹配返回文件不可用或防御性恢复失败，不读取/删除对象、不改状态及审计。进一步以limit=1、旧Bucket候选排首复现恢复饥饿，现将Bucket过滤下推PostgreSQL候选查询，同时保留服务防御校验。正常查询不会返回其他Bucket候选，因而不会把其计为当前Bucket失败，也不会修改其时间来绕过队列问题。
