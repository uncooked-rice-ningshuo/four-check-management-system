# 组织归属有效引用（2026-10-04）

页面已有启用选项过滤，后端分配事务此前仅依赖外键：停用部门或组织角色仍能被分配，不存在的引用返回数据库内部错误。临时 PostgreSQL 的四个新增回归均先失败，确认该缺口。

`Postgres.AssignUserRole` 现在先检查引用 UUID，再按部门、组织角色的固定顺序查询启用记录并持有 `FOR SHARE` 锁，直至账号、组织归属、会话撤销和审计事务提交。无效或停用引用返回已有 `ErrInvalidInput`，HTTP 为 400 `INVALID_REQUEST`；其他数据库故障继续传播为内部错误。锁防止校验后、提交前引用被停用。没有改变停用账号本身能否由管理员调整归属的规则，也没有修改已有历史归属。

## 验证记录

- 实际 PostgreSQL/race 新增部门/角色停用、缺失与非法 UUID 六种情况。停用发生在服务读取账号后、仓储写入前；断言账号版本和归属不变、没有组织关联或审计写入、原会话仍可使用。首次修复后复验因测试 SQL 混用 UUID/text 参数失败，修正测试显式类型后重新运行，不计该次为通过。
- HTTP 测试在原 401/403/404/409 覆盖之外增加引用错误 400/稳定错误码。
- 实际 PostgreSQL/race 最终24项通过（40.786秒）；Chrome154.0.8037.97隔离浏览器3d0569a756共11场景通过，异常/清理错误0，验证启用归属正常写入和409保留/重试兼容。无效引用六种结果由独立实际PG用例证明，不将浏览器故障注入当作数据库并发证据。
- 修改的Go文件已gofmt；HTTP聚焦测试、`go vet ./...`、`go test ./...`、`go test -race ./...` 通过。默认全量含缓存结果和未配置外部服务时跳过的集成测试，数据库证据以本项显式一次性PG/race执行为准。前端 `pnpm lint`、`pnpm test`（65文件314项，286.08秒）、`pnpm build` 通过；既有jsdom样式提示和2.17MB构建chunk警告仍在。本项结束额度剩余5%，按用户停止线不启动下一项。
