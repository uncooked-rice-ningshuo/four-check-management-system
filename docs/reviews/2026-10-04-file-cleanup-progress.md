# 文件恢复队列持续推进（2026-10-04）

实际 PostgreSQL/MinIO 以3个FAILED源文件、单次limit=1复现：最早文件删除失败后仍排首位，后续候选饥饿；删除成功也没有持久化完成状态，会反复入选。

015只追加迁移增加files.object_removed_at及候选部分索引，约束只有FAILED文件可以记录删除完成。恢复查询排除已删除对象；每次删除尝试与审计共同落库，成功设置标记、失败更新updated_at使其让位。失败状态和原错误码保持，FILE_OBJECT_REMOVED / FILE_CLEANUP_FAILED只表达对象清理结果。Discard、上传失败及Reconcile复用此逻辑。删除与数据库之间无法组成单一事务，若对象已删除但标记/审计失败，候选保留，下次对缺失对象重试后补齐标记和审计。

就绪检查要求新列存在；缺015不能宣称依赖就绪。部门流程迁移暂排016，仍须业务粒度确认，不因本次迁移顺延而批准任何业务规则。
