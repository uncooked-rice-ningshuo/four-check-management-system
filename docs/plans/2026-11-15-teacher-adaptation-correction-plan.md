## 当前状态与边界

代码已实现，隔离环境专项通过，尚未完成用户整体业务验收。最近一次核查时宿主 8080 仍为本轮修改前进程：最新班级关系校验待加载并复验。未提交、推送或部署。

## 最新确认的交互规则

- 学年维护大一至大四对应入学年级，同时决定年级部匹配与通报覆盖；移除学期独立维护入口。
- 每个模块的角色列头配置有效期，同角色在该模块的默认动作共用期限。浮层修改只更新草稿；确定后更新摘要，取消或点击外部关闭放弃修改；页面“保存修改”统一持久化。
- 未承担业务时，部门功能及角色权限入口禁用；动作未开放时不显示范围入口。底层保存配置保留，不显示为已生效。
- 范围由单元格打开独立弹窗，取消不应用。班级可多选，按同组固定年级与专业交集过滤；上级变化清除不匹配班级。个人权限与模板使用同一编辑器。
- 保存端查询真实班级关系，个人授权新增、修改及模板保存均拒绝矛盾组合，错误码 OPERATION_RANGE_CONFLICT。动态年级阶段仍按实际业务学年解析。
- 权限详情合并默认授权与当前结果，个人设置单列。日期使用区间选择；无范围能力不显示范围控件。“适用部门”只选择授权业务路径，不分配新部门。
- 不增加初始化按钮或技术性告警。角色保存刷新用户、有效权限与个人设置缓存。
- 沿用现有 Ant Design 风格，表格内横滚，弹窗内容滚动且操作按钮可达。

## 业务规则 4. 动作及数据范围清单

“数据范围”在此特指年级、专业、班级；权限中的旧学年/学期/周次范围全部移除，以具体日期起止表达有效期；检查类型仍是动作所属业务维度。业务记录、通报查询中的学年/学期/周次字段不删除。

| 动作 | 本次是否增加数据范围 | 规则 |
|---|---|---|
| USER_MANAGE、PERMISSION_MANAGE | 否 | 不按学生年级班级过滤管理能力；不借本轮扩展管理端授权对象 |
| MASTER_DATA_MANAGE、DICTIONARY_MANAGE、CONFIGURATION_VIEW | 否 | 保持现有能力，不拆基础数据细粒度权限 |
| INSPECTION_ENTER | 是 | 按检查类型约束手工录入、导入确认及现有录入与提交能力 |
| INSPECTION_MANAGE | 是 | 修改、删除；同时校验原对象及改后目标 |
| INSPECTION_REVIEW | 是 | 按批次所属部门授权审核，不混用其他部门范围 |
| INSPECTION_VIEW | 否 | 延续现有查看规则；操作范围只用于默认筛选 |
| INSPECTION_EXPORT | 否 | 与查看授权一致；尚未交付导出功能不在本轮实现 |
| MORNING_SCHEDULE_MANAGE | 否 | 配置早签计划管理动作，不增加班级级计划流程 |
| REPORT_FILE_OUTPUT | 否 | 生成并下载 Word/Excel，独立于生成草稿；按可访问周次及版本输出 |
| REPORT_VIEW、ARCHIVE_VIEW | 否 | 全量通报；保留适用的既有权限条件 |
| REPORT_GENERATE、REPORT_CORRECT、REPORT_REVIEW、REPORT_RETURN、REPORT_FINALIZE | 否 | 整份版本操作，不按班级拆通报 |
| REPORT_FORCE_GENERATE、REPORT_OBLIGATION_MANAGE、REPORT_OUTPUT_SETTINGS_MANAGE | 否 | 独立配置动作，保留原业务校验 |
| REPORT_PUBLISH | 否 | 不因已有枚举交付未实现发布渠道 |

范围一条条件内取交集，多条条件取并集。完整授权包含来源部门、动作、检查类型、范围、有效期，不能分别合并动作集合与范围集合后做笛卡尔组合。普通部门当前不配置年级范围；年级部按映射设置。个人范围可以调整，但提交/审核仍不得突破目标部门本身职责。

## 业务规则 5. 模板补齐与移除角色硬判断

### 业务规则 5.1 已有模板的动作

记录查看、录入与提交、管理、审核，以及通报查看、生成、修正、审核、退回、定稿、输出设置、归档，沿用现有开关。移除权限计算、授权保存、有效权限解释、业务服务和前端中额外的部长/副部长条件。老师与主席团配置入口补齐；角色仅用于匹配默认模板。

定稿后更正本轮沿用 REPORT_CORRECT：有此有效权限则按现有更正版本流程执行，不新增第二个业务审批。CanReviseFinalizedReport 如继续供前端使用，由最终权限推导，不再由角色名称推导。

### 业务规则 5.2 缺少模板入口的已实现能力

| 能力 | 本轮修改 |
|---|---|
| 早签计划管理 MORNING_SCHEDULE_MANAGE | 在早签相关配置增加部门功能开关及角色默认开关；个人授权可增减；移除 SPORTS + MINISTER/VICE_MINISTER 硬授予、硬拦截 |
| 强制生成 REPORT_FORCE_GENERATE | 通报部门/角色模板增加独立开关；移除办公室负责人资格；保留强制生成确认、原因及审计 |
| 应交管理 REPORT_OBLIGATION_MANAGE | 通报模板增加独立开关；移除办公室负责人资格；仍属于唯一通报维护部门职责 |

按新规则初始化模板和测试账号：早签计划、强制生成、应交管理使用明确开关，不继承旧测试账号授权。老师默认查看及文件输出，写动作默认关闭，可配置。

检查导出、发布枚举或隐藏字段不等于已交付：本轮去除相关通用角色硬限制时不能误显示不可用按钮，不补造导出/发布业务。

### 业务规则 5.3 保留哪些判断

保留账号有效性、最终动作权限、部门职责、数据范围、有效期、状态机、版本、锁定、幂等、审计和唯一通报维护部门约束。不将管理员技术权限或原专用归集路径无意授予普通账号。只保留“哪些角色可绑定多部门”这类已确认组织规则，不能拿它限制已获授业务动作。

## 业务规则 6. 默认与个人权限计算

1. 读取账号角色及有效部门关联。
2. 授予时，每个部门按部门功能与当时角色模板形成默认授权快照，保存模板版本、动作、范围及实际起止时间；运行时读取已授予快照，不随最新模板自动重算。部门业务职责、账号状态和成员关系仍实时校验。
3. 在对应授权来源上应用个人修改/禁用，加入个人新增授权。
4. 去除未生效、已到期、部门已退出的授权。
5. 完整授权项取并集；明确的个人全局拒绝优先。
6. 对部门提交、审核按目标部门授权判断；通报按承担部门配置判断；查看沿用原可见规则，不将写范围套到读权限。

个人“修改”覆盖原来源条目，不能一边保留宽范围默认授权一边新增窄范围授权，导致收窄无效。个人“删除默认项”持久化为禁用；“删除个人新增”只删除该新增；“恢复默认”清除覆盖，恢复该用户已授予的默认授权快照，不隐式应用新版模板。新增或扩大动作可绕过角色默认关闭，但不绕过部门未承担业务、账号退出部门等业务边界；延续现有管理员独立授权机制，不扩展其范围。

### 业务规则 6.1 个人权限审查 case

| 场景 | 预期 |
|---|---|
| 已按模板授予、无个人设置 | 使用授予时的默认授权快照 |
| 禁用某来源默认录入 | 该来源不再授予；模板重存不能复活 |
| 恢复默认 | 清除覆盖，恢复原已授予默认快照，不自动续期 |
| 将某来源范围从全年级改为某专业 | 替换该来源范围，不能仍获得该来源全年级 |
| 新增模板未开启的审核动作 | 部门承担该业务且个人有效授权时可执行，不查角色名 |
| 老师有年级部录入和学习部审核 | 各自按对应动作范围执行，不串用 |
| 禁用年级部录入但学习部仍允许 | 学习部来源仍有效；详情显示原因 |
| 禁用账号全部录入 | 使用明确的全局个人禁用，压过所有来源 |
| 删除个人新增但模板仍允许 | 仍允许，页面提示仍存在默认来源 |
| 模板二次修改并生效 | 已授予用户的动作、范围、期限及个人设置均不变；后续新授予使用新版 |
| 退出部门 | 该部门默认及依附该部门的个人授权失效 |
| 个人覆盖到期 | 按第7节已确认规则处理，不能静默恢复更宽权限 |

## 业务规则 7. 有效期

生效点为角色/部门实际授予时间。委员、部长、副部长、主席团的模板初始值为一年，可改为两年、三年等；一年不是代码常量或强制上限。老师也由模板配置，未设置表示无到期时间。允许固定截止日期或默认时长，前端显示最终起止时间。

角色变化使旧角色默认授权结束，新角色从生效时点重新计算。新增部门只启动该部门授权，不延长其他部门。改姓名、重新登录、普通保存不续期。后端实时判定有效期，不能只依赖前端按钮或定时清理。

已确认：模板初始一年可改两年、三年；从实际授予时间起算；角色变化重新计算新角色默认权限；个人权限使用具体起止日期，不使用学年/学期/周次作授权期限。

已确认的具体行为：
1. 模板修改不追溯已授予用户。例：甲按旧模板获授一年，模板改两年后甲仍维持原权限及截止日；乙之后获授使用两年。此规则不只适用于期限，模板动作和范围修改同样不自动覆盖旧用户。
2. 个人截止日期到了，该项权限停止，不自动回落模板。例如个人设置12月31日截止，1月1日不能因模板还有效而继续操作。管理员可以明确续期或恢复原默认授权。
3. 委员改部长时，新角色默认权限从此次授予重新起算，使用当时模板；页面列出既有个人新增、修改和禁用，由管理员明确保留或清除，提交后原子生效，不偷偷迁移或删除。

日期输入按用户理解包含截止日当天。例如截至12月31日，则当天可用，次日零点失效；服务端时间边界和缓存刷新属于实现要求，不单独请用户审批。到期不删除已提交记录，其他有权账号可继续办理。

## 业务规则 8. 记录、提交、审核适配

记录属于独立业务数据，创建人及来源部门只用于追溯，不作为提交路径限制。多部门账号本人创建的记录，可以按本人所属且负责该业务的部门选择提交路径。不能要求记录先归属于目标部门。

提交时选择部门，服务端检查本人所属部门、该部门业务职责、对应有效权限及配置的数据范围，同时保留状态、版本、锁定及重复提交校验。年级部不写死年级限制：只有对应权限配置了阶段映射或明确范围，才按该配置判断。普通部门同样使用配置，当前不配置年级范围。

case：张老师同时属于学习部、大一年级部，两部门都承担到课率。张老师创建一条到课率记录，提交前可以选择学习部路径，也可以选择大一年级部路径，只要选中路径的权限及配置范围满足。选学习部则由学习部流程审核；选年级部则由年级部流程审核。这是同一记录的可选路径，不是创建来源部门之间的转移，也不是同一记录同时重复提交两次。补充已确认 case：大一年级部授权配置只允许该学年映射的大一年级，学习部授权不限制年级。若张老师创建的是大二学生记录，只能选择学习部路径；不能提交给大一年级部。限制来自所选路径的权限配置，不是部门名称硬编码。

候选查询、首次提交、幂等重放、退回重提、导入记录提交统一适配。创建信息不改写，提交信息独立保存。已进入有效批次的记录不能重复提交。零记录仍按目标部门应交单元及权限处理，不新建审批流程。原管理员专属记录规则不随本次普通多部门支持自动放开。

## 业务规则 9. 通报、查看与文件

通报维护部门保持唯一；账号属于该部门且取得相应有效权限即可操作，不要求部长等角色。多部门资料加载必须能发现账号所属的维护部门，不只检查主部门。

不新增班级级通报过滤。查看、草稿、修正、审核、定稿及历史更正各按已有动作执行；个人授权及有效期统一生效。

通报下载保持现有操作：选择周次、版本和格式，点击下载。有对应有效权限就允许，没有就拒绝；不新建老师下载流程，不引入文件队列或额外审批。老师所属学生会办公室承担通报业务时，按该部门模板及个人授权取得能力。

已确认拆分通报权限：保留 REPORT_GENERATE 表示生成通报草稿；新增 REPORT_FILE_OUTPUT表示生成并下载 Word/Excel，Word 和 Excel 共用一个输出动作，不增加新页面或工作流。两项均在部门功能、角色默认模板、个人权限和有效权限详情中配置；无年级/专业/班级范围。原输出接口改查文件输出权限，前端下载按钮同步；去除 restrictReportMemberToDraft 的委员角色限制。选择周次、版本、格式后下载的操作不变，仍需具有该报告版本的访问权限。查看/下载权限不附赠生成草稿权限。

按新规则分别初始化草稿生成和文件输出开关，不转换旧测试账号的权限。新老师默认查看及文件输出，草稿生成关闭。

### 业务规则 9.1 日常检查记录及提交页面（已确认）

取消主席团角色额外按主部门创建来源过滤的限制。数据和按钮统一按当前页面对应部门的有效权限判断，不因角色名称新增限制，也不把操作范围强加给查看。

case：老师同时拥有学习部和学办的权限，在到课率页面中，分别看到这两个部门在对应权限场景下允许其查看、提交或审核的数据和功能。有学习部审核权限，就能看到并处理学习部待审核批次，不能被学办只读规则一并隐藏；学办本来只允许读取已确认来源的场景，仍按原逻辑处理。不是因为加入两个部门就能看全系统所有数据，也不额外开放未确认来源。

### 业务规则 9.2 通报页面（已确认）

学办是唯一承担通报业务的部门。上述老师进入通报页面，只按学办的通报权限显示对应数据和功能；学习部及其他部门的检查权限不能用于查看或操作通报。全量通报内容与所属业务部门是两个概念：有权查看学办通报时，其文件仍可包含全年级数据。保持现有通报流程，不新增老师专用视图或审批。

## 4. F02：权限详情与状态

## 7. F06：同业务权限与可见性

**问题性质**：代码风险，当前尚无实际越权复现；用户已同意验证后修复。

**位置**：`internal/permission/service.go`内ConfirmedOnly推导、对应SQL查看过滤及相关测试。

先构造“学办到课率写权限被拒绝，但另一检查业务写权限仍允许”的场景。判断到课率未确认数据可见性时，只使用同来源、同检查类型的有效写权限，并执行拒绝优先；不能用另一业务仍有写权限来放开当前业务。学习部与学办两个来源仍独立，不新增查看范围，也不以角色名判断。

**验收**：业务A拒绝+B允许不放开A；A允许不误伤B；一个来源禁用不抹除另一来源；办公室只读仍限已确认；有对应写权限按现有规则可处理未确认数据。若复现不成立，记录证据，不进行推测性修改。

## 8. F07/F08：配置提示、默认筛选与链路

- 在录入、导入确认、候选、提交、审核及通报等实际依赖映射的环节，明确提示缺失的学年/阶段。返回稳定错误码，前端保留输入和清单；不将配置错误表现成成功空列表。
- 普通部门不依赖缺失映射的权限仍可使用；完整有效来源可授权时，不能被另一个缺映射来源全局阻断。
- `useInspectionListScope.ts`及各检查页使用适用权限范围提供可清除默认筛选；用户明确选择或清除后不反复自动覆盖，切换账号/业务时重新确定上下文。
- 只将现有筛选控件能准确表达的范围应用为默认值；多组并集不能强行变成单个班级/年级而误导，不新增通用规则筛选器。查看仍由既有查看权限决定。
- 保留已确认的记录创建来源与提交路径分离。大二记录学习部可提交、大一年级部不可；切换路径保留清单并标明冲突；重复提交、退回重提、导入确认后的范围与期限重新验证。
- 工作台仍统计本人待办；不把部分范围的能力表达为整个部门的完整操作能力。
