# 模块一：处分配置实施方案

2026-11-16 · 主 Agent 汇总 A、B 两份独立方案并结合当前项目取舍。此文限定模块一实现，不代表已完成或部署。

## 范围

- 本期交付一个处分配置入口中的两项能力：处分规则版本管理、处分累计组/合并配置。
- 规则按全院默认版本维护，不按学期另建规则，不新增条款库页面。
- 不实现处分文件配置、文书模板/生成/打印、学期违纪台账、待处分、处分归档、提醒、处分记录或自动重算任务。
- 规则编辑与发布沿用系统管理员/超级管理员配置边界；“辅导员”对应老师角色，但不因此获得规则配置权。
- 使用当前检查类型目录，不在代码里写死部门与检查类型映射；规则快照保存类型标识和发布时名称，供历史查看。

## 页面与交互

### 页面设计方向

- **产品**：系统管理员为学院配置检查项如何累计、如何换算，以及每个累计结果对应的处分档位。
- **气质**：清楚、克制、可核对。
- **使用场景**：学院日常管理后台中的正式规则配置，不采用营销页视觉或装饰性数据卡片。
- **重点画面**：第一步能看清“哪些检查项归到哪个累计项”；第二步能读懂每个来源数值如何换算并汇总。
- **识别细节**：同一累计项在四个步骤里保持相同名称和标识，使“成员 → 公式 → 档位”的关系连续可见。

本页按累计规则的建立顺序组织为四步配置器：**归组并命名 → 确认计量与换算 → 配置处分档位 → 检查并发布**。页面一次只聚焦当前步骤；顶部步骤条显示已完成/当前/未完成，底部有上一步、保存草稿、继续或发布。不是把所有规则控件、版本历史与操作按钮同时堆在一屏。

### 第 1 步：归组并命名

- 标题解释任务：“把参与同一项累计的检查项放到一起”。主体为“未归组检查项”和“累计项”两块；检查项清单从管理员目录读取当前启用的全部检查维度（目前为 8 项），不从组成员反推，也不硬编码数量。每个维度始终存在于未归组区或且仅存在于一个累计项中。
- 用户把检查项拖到“新建累计项”投放区时创建一个新组，首个成员名称可作为可编辑的默认组名；把另一个未归组项拖到某个已存在组时并入该组。累计项数量由用户归组结果决定，不固定为 8。名称直接在累计项行内编辑，不另放在表格下方。
- 每个累计项行提供组内成员管理和删除组操作。将成员移回未归组区或删除累计项时，成员返回未归组列表，不删除检查维度；新建空组不允许保存，组内所有维度移出后该空组可删除。删除/移出后页面明确反馈，允许撤销最近一次归组操作。
- 拖放落点高亮，拖拽取消不改变归属。对应的键盘替代（选择检查项、目标累计项并移入/移出）与“新建累计项”投放区放在双栏卡片上方；宽屏尽量单行排列，空间不足时选择器占满一行、按钮在下一行靠右。组行直接提供名称、成员移出和删除操作，避免用户滚到长列表末尾才能分组。
- 只有管理员目录中的全部启用检查维度均被恰好归入一个已命名且非空累计项，才能确认本步进入下一步。首版草稿不预建 8 个累计项，而是从当前启用检查项目录建立未归组清单；后端发布校验同样保证每个启用检查维度恰好归属一次。

### 第 2 步：确认计量与换算

- 一次编辑一个累计项，标题保持累计项名称；上方展示其成员检查项。先设累计单位，再按成员逐行设换算系数与加减操作。界面用语义明确的控件，不要求用户编写表达式。
- 每行公式直接展示为“检查项原始值 × 系数 [加/减] → 累计项单位”；同单位系数默认为 1，但仍可核对。不同单位须显式确认正数系数后才算完成。
- 给出一个只使用用户手动输入示例值的即时预览：逐项换算过程、合计值和当前规则配置状态。注明“示例计算，不读取学生记录”。不显示学生数或处分影响数。
- 只有所有累计项均有单位且公式完整，才能进入处分档位。返回第 1 步并改变归属时，只将受影响累计项的单位/公式标记为需重新确认；未受影响组保留进度。

### 第 3 步：配置处分档位

- 逐个累计项配置处分档位。处分名称使用可编辑输入框，五个标准名称默认按“通报批评、警告、严重警告、记过、留校察看”建立；下方展示当前启用字典名称作为快捷填入项。稳定档位 code 和字典顺序控制档位规则，名称可自定义并随版本快照保存；同组名称须非空且不重复。新增档位时按当前启用字典项的排序依次选取下一个未使用 code；字典中文名称只作为名称输入框下方的快捷填入项。若新增档位排在末尾，需由用户明确输入大于当前最高档起始值的新阈值；该值同时成为前档结束值与新档起始值，系统不推算或默认阈值。误加档位可从当前草稿移除。默认老师确认规则沿用既定设置：通报批评免确认，其余档位需要确认。
- 区间统一为 `[起始值, 结束值)`，最高档结束值为空并显示“无上限”。在表格顶部显示当前累计单位，区间编辑时带出该单位。错误贴近字段，服务端多字段错误在修复一项时只清除该项与确实关联的边界错误。
- 配置过程中显示当前组规则摘要，避免用户在档位表里失去“此档位属于哪个累计项”的上下文。档位显示名称允许自定义并随版本快照保存；此页只配置处分规则，不创建学生处分记录。
- 改变第 1 步归属时，受影响累计项的处分档位进度也需重新确认；改变第 2 步单位/换算时，受影响组档位标记需重审。其他累计项继续保持已完成状态。

### 第 4 步：检查并发布

- 以可读的组块列表回顾每项累计项的名称、检查项、单位、换算公式及已选档位区间/依据/老师确认要求；摘要不提供页内修改或跳转，用户通过步骤条手动返回配置。
- “校验规则”逐组检查成员归属、单位、系数、公式和区间连续性。失败时用轻量 message 提示，步骤条标记有问题的步骤；不自动切换步骤，也不在摘要列出修复链接或聚焦字段。
- 点击继续或步骤条向前时按顺序校验将离开的每一步：归组步骤检查唯一组名和唯一归属；计量步骤检查单位、正整数系数和运算符；档位步骤检查启用字典 code 顺序、档位名称、依据、整数边界、连续区间及唯一最高档无上界。失败留在当前步骤、显示 message 和可定位字段的 inline 错误；归组错误用本步提示。用户可手动点击错误步骤修正。Step 4 服务端校验作为发布最终防线。
- 通过后“发布为默认规则”进入确认。确认只说明该版本成为全院默认规则、本次没有学生影响数量或后续待处分重算结果；发布后版本只读并写审计。

### 版本、保存与状态

- 页头显示当前生效版本、草稿版本和最后保存时间。首次进入仅提供“新建规则草稿”；已有草稿时提供“继续配置”，不允许并行草稿。草稿创建时复制当前已发布快照；首版建立空的累计项集合，由用户从启用检查项目录逐项归组，不预建固定 8 组，也不填未知单位、阈值或依据。
- 自动保存不假装已持久化；仍以明确“保存草稿”操作和保存成功状态为准。同一草稿的四步之间切换时保留本地未保存输入并直接继续，不弹出离开确认；离开编辑区、切换版本、进入历史或离开页面时，才提示保存并继续、放弃更改或留在当前配置。网络失败保留用户输入；版本冲突提示加载最新草稿，不能静默覆盖。
- 版本历史放在独立的只读入口/抽屉，不混入四步编辑器。显示版本号、状态、创建人/时间、发布人/时间、生效时间及差异摘要。查看历史不暴露编辑控件。
- 初始加载、无生效版本、无草稿、读取失败、无权限、草稿冲突分别有对应状态；失败可重试，不能用空状态掩盖错误。
- 拖拽提供醒目的把手、目标反馈、取消后还原和可访问的替代操作；步骤、表单和列表支持键盘与可见焦点，窄屏将归组区纵向排列、公式/档位内容在自身容器内适配或滚动，不裁掉关键字段。

## 规则与发布边界

- 换算系数和处分档位阈值只允许整数：前端即时限制，服务端权威拒绝非整数；底层 numeric(12,6)/(12,4) 保持既有存储精度，无需迁移。数值仍须有限且不超出数据库最大范围。累计组阈值有序、不得重叠，档位间不得有未定义空档，最高已选档位上界为空，且每组至少保留一个档位。闭开区间使用 `[lower, upper)` 统一语义。
- 只有配置完整且服务端校验通过的草稿能发布；一次只允许一个当前发布版本。已发布版本不可修改，发布需并发版本号检查并原子切换当前版本。
- 发布保存完整规则快照和操作审计，重复发布拒绝；审计失败或并发冲突时当前版本不变。
- 发布前逐组展示结构化摘要：累计项名称/单位与编辑入口、成员标签、逐来源换算式、处分档位独立条目（名称、含单位区间、依据、老师确认方式）。依据为空显示“未填写依据”。内容允许换行；处分档位仍保留表格结构，窄屏在表格自身容器中横向滚动。本期预览只做规则配置自身的公式示例和档位命中检查，不展示伪造的真实学生影响人数。
- 发布校验失败使用轻量 message 提示，不展示顶部或 Step 4 校验 Alert，不自动跳步、选中累计项或聚焦字段，也不提供“前往修正”按钮；问题步骤以 error 状态标记。用户手动返回相应步骤后，字段级错误仍显示在对应控件旁，修正时按字段清除关联错误。
- 产品方案中发布后对 INIT/DEFERRED 的重算、作废重建与通知依赖待处分模块，而该模块不在当前实现范围。本期记录新的默认规则版本，不创建不存在的下游事项、不声称执行过重算；后续模块接入时必须按产品方案实现这一联动。
- 配置阶段的单位和累计值只是供未来台账解释的规则定义。本期不读取通报数据，不推导各检查类型的学生累计口径。未配置的检查类型计量语义不得用来发布完整规则。

## 项目结构

- 后端新增独立 `disciplineconfig` 领域/应用包；校验与版本规则放该包，数据库读写继续放 `store`，HTTP 适配放 `httpapi`，由 `cmd/api` 装配。
- 前端新增 `features/discipline-config`（领域类型、API、查询/变更 Hook、规则编辑与合并 UI）和路由编排页；请求只经 `shared/api/httpClient`。
- 新增只追加数据库迁移；用规范化的规则版本、累计组、来源项和档位表保存不可变快照，不把可检索字段塞入一整块 JSON。
- API 只提供当前/历史版本读取、草稿创建与整体更新、草稿校验、发布。写请求必须限制体积、拒绝未知字段、检查状态与 `rowVersion`；管理员路由和服务端检查同时生效。
- 审计在同一数据库事务写入；发布状态切换与当前版本指针更新保持原子。

## A/B 独立方案裁定

A、B 均建议独立处分配置领域、不可变版本快照、管理员权限、完整草稿编辑/发布路径、受约束的加权求和、服务端校验与审计。本方案采纳这些共同结论。裁定需收紧的分歧/风险：以现有检查类型目录而非硬编码部门映射提供来源；初始单位和处分阈值不造假；不实现台账、待处分或档案底座；真实待处分影响预览与发布后重算留给其依赖模块。本期不增加页面、外部服务或运行时依赖。


## 2026-11-17 批注调整

- 来源单位按检查类型代码映射：到课率为“学时”，其余当前事件型检查为“次”；页面始终按检查类型目录回显，不使用存量草稿字段值，后端在保存草稿、校验和发布前规范化旧值。发布时如存在旧单位/标签值，先将规范化快照写回草稿再发布。累计单位、系数和加减关系仍由管理员配置。
- 全量启用检查维度始终显示归组状态；已归组项不支持从来源清单拖动，需先从原累计项移出或通过明确的选择操作调整归属。
- 页面只保留页头版本信息，不再重复显示编辑版本栏。
- 处分档位复用系统字典；前端先读字典类型，再按类型 ID 读取启用项；服务端在保存/校验/发布时读取同一组启用项，以启用 code 和排序校验等级；自定义名称保存在版本快照中，不以字典 label 覆盖。草稿允许从标准档位中选择子集并移除档位，发布校验要求至少一档、编码不重复且按字典顺序、区间连续、最高档无上限。

## 2026-11-18 页面批注调整

- 处分配置默认进入当前规则只读页；点“修改配置”后进入独立编辑页。名称和依据默认以虚线边框只读按钮呈现，点击进入编辑并明确保存/取消；依据编辑使用多行文本框。
