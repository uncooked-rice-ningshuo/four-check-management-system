# Server-managed Master Data and Course Scheduling Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Remove administrator-maintained artificial codes from master data, use backend-generated UUID relationships, and support multi-class courses with validated semester/weekday/period schedules.

**Architecture:** Existing UUID primary keys remain the only technical identifiers. Real-world identifiers (student number, employee number, dormitory room number, and classroom location) remain business fields, while artificial `code` columns are removed from code-less master-data tables. Student numbers and employee numbers are entered when a record is created and remain immutable afterward. Course names are unique canonical business names; courses use junction tables for participating classes and structured schedule rows. Each schedule belongs to a semester and validates weekday 1–7 and periods 1–10 at 45 minutes per period, with both application validation and a PostgreSQL exclusion constraint preventing overlaps.

**Tech Stack:** PostgreSQL migrations, Go 1.25/Gin application services, React 19/TypeScript, Ant Design ProTable, TanStack Query, Vitest, Go test.
