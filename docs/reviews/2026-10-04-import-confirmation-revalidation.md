# 导入确认事务重校验（2026-10-04）

## 问题与修复

在一次性 PostgreSQL 中先完成两行预览，再停用其中一名虚构学生，旧代码仍成功写入整批记录。复现输出：`student disabled: stale preview was committed`。原因是确认事务只验证批次状态、版本、归属和预览结果，未重新验证可能已变化的基础数据。

确认事务现在先锁定有效的学期、周次、学年、部门、检查类型及录入映射，再检查并锁定学生、班级、年级、课程班级关系、教室楼栋及课程安排。重新应用当前周次的日期/字段规则；班级或年级归属变化必须重新预览。名称等预览快照不被后台静默改写。检查在任何业务写入前完成，关联失效返回 409 `IMPORT_PREVIEW_STALE`，保留原批次状态、版本及预览，前端提示重新上传校验。

预览之后出现相同检查记录时，唯一约束继续保护并发写入；确认代码只将已知去重约束映射为 409 `RECORD_ALREADY_EXISTS`，其他数据库故障仍保持内部错误。真实 PostgreSQL 首先复现了原始 23505 被错误归为内部失败，再验证领域冲突、整批回滚与移除冲突草稿后重试。

恢复同一关联后仍可使用原版本与幂等键重试；新事务重新检查。已确认批次的同键重试仍先返回既有结果，不因之后基础数据停用而重复写入或误报失败。
