# 文件恢复命令最小设计

范围依据：既有存储服务已具备PENDING恢复与FAILED清理，但运行环境没有调用入口；当前已补齐清理进度、Bucket隔离、读取上限和并发/临时失败保护。按持续实施授权补齐独立命令，不自动执行业务数据恢复。

选择独立CLI复用storage.Service.Reconcile。管理页面会增加新权限/API/导航，不是当前需要；后台定时任务会引入无人值守的执行时机，本次不采用。命令不迁移、不建账号、不列举Bucket、不操作AVAILABLE/MISSING文件、不启动定时器。

默认预览：要求DATABASE_URL和MINIO_BUCKET，检查数据库就绪，按配置Bucket、更新时间和limit查询候选，只输出ID/状态/大小/更新时间及计数，不访问对象、不写状态或审计。预览只描述本次查询，后续apply会重新查询。

显式执行：--apply，同时提供--actor-id和非空--reason（不超过255字符）。账号须ACTIVE、超级管理员、已完成强制改密。MinIO配置及最大文件大小必须明确；操作前检查对象存储就绪。单次limit默认100、范围1–1000；older-than默认1小时、至少5分钟，避免处理正常上传；timeout默认60秒、范围1秒–5分钟。按现有服务记录文件审计；任一候选失败时输出统计但返回失败退出状态，不把部分成功当全成功。

验证：参数和安全配置单测；一次性PG/MinIO实际验证默认预览零写入、缺迁移拒绝、禁用/普通/强制改密账号拒绝、Bucket隔离、时效和上限、PENDING恢复、FAILED清理、暂时失败及重试、审计和安全输出。继承存储真实回归，后端gofmt/vet/full/race。无前端或业务API变化，不重复前端全量；目标环境恢复和业务写入仍需另行授权。
