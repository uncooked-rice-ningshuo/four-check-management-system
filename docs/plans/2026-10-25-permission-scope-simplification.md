# 检查权限范围简化

## 已确认规则

- 用户单独授权/限制只按学年、学期、周次和检查类型配置，不提供部门、班级、年级范围。
- 按部门与检查类型映射获得的检查动作仍由账号主部门的映射决定；映射只决定账号拥有哪些动作和类型，不再把记录查询、导入确认、审核或导出限制到该部门。授权类型后按该类型跨部门访问。
- 普通成员新增记录或导入时，记录归属仍固定为账号主部门；可选“目标部门”仅用于有权人员显式指定业务归属。
- 导入批次由学期、周次、检查类型和归属部门确定。Excel 中的班级、年级由服务端解析和校验，不要求用户先选目标班级或年级。
- 学生、班级、年级仍是检查记录和基础数据的业务字段，也可作为列表查询筛选；它们不再是用户授权范围。

## 旧权限规则转换

- 旧 ALLOW 规则清除部门、班级、年级范围，保留学年、学期、周次和检查类型，表示授权范围按新规则扩大。
- 旧 DENY 规则若依赖部门、班级或年级才成立，则停用并清除这些范围，避免变成对所有部门/班级的全局拒绝。旧记录通过追加审计保留前后值和迁移原因。
- 受影响账号递增会话版本并撤销刷新会话，要求重新认证后按新范围生效。
- 历史导入批次的 class/grade 字段保留用于读取和完成已存在批次；新批次不写这些范围。

## 实施与验证

1. 更新权限服务：映射权限不带部门范围；新建/更新的用户规则拒绝部门、班级、年级范围。
2. 用追加迁移归一化旧权限规则、写审计并失效受影响会话；只在一次性 PostgreSQL 中验证。
3. 删除用户权限维护中的“高级数据范围”控件和导入抽屉中的目标年级/班级控件。
4. 移除新导入 API 中 classId/grade 目标契约，同时保持已有批次读取与确认兼容。
5. 同步 AGENTS、PRD、技术方案、原型和项目状态；历史验收记录保留并标记为已被新规则取代。
6. 覆盖权限跨部门读取/写入、角色映射类型隔离、旧 DENY 停用、规则输入拒绝、Excel 多班级预览/确认、旧批次恢复，并运行前后端适用完整检查。

## 影响边界

检查动作从部门映射仍按账号主部门决定，但匹配到的类型将跨部门生效；这也适用于录入/管理/审核/导出等映射提供的动作。普通成员不能把新记录归到其他部门。业务列表中的班级/年级搜索筛选和学生/班级基础数据关系不删除。
