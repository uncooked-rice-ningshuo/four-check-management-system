# 周通报 Word/Excel 输出与阶段三后续路线图

> **2026-11-08 方案补充：** [拼装式生成独立方案](2026-11-08-modular-weekly-report-word-excel-plan.md)细化了通报说明与检查 Word 按页拼装、各类型单项文件、Excel 多工作表和可配置默认检查。以下旧路线图中的代码与环境状态是当时证据；实施前按 `docs/project-status.md` 和当前源码重新核查。

**目标：** 在保持通报结构化数据为唯一业务权威的前提下，补齐按指定草稿/定稿版本生成、保存和下载 Word/Excel 文件的能力，并完成隔离环境和目标角色验收。

**架构原则：** 周报状态机负责数据草稿、审核、退回和定稿；规则指标在创建草稿数据版本时计算并作为该版本的结构化数据快照，审核与数据定稿沿用该值。Word/Excel 是按规则将所选数据版本（含已保存指标）转换为可查看文件的独立输出；输出任务不得计算或回写指标、改动报告版本或触发审核、定稿、发布等状态转换。

**技术范围：** 复用 Go API、PostgreSQL、现有私有对象存储和 React/TanStack Query 前端；先核对现有生成和存储能力。需要新增运行时依赖或外部渲染服务时，按仓库规则单独确认。

## 路线图

> **范围与依赖更新（2026-11-07）：** 本文阶段 2–6 是文件输出路线。指标口径、所需数据和公式已冻结；指标计算、版本快照与工作台/归档展示已有本地代码，仍需验证和环境验收。文件生成只读取这些快照。原 v1 规格中“文件不含指标”仅是此前版本的决定，不再作为当前目标。

### 阶段 1：冻结输出规格

**目的：** 让 Word/Excel 生成器有明确、可验收的输入和版式规则。

**状态：字段/版式规格已完成；指标数据层与版本页面已有本地实现，验证及运行环境加载待完成。** 八类字段映射、基础状态展示、版本绑定、命名、模板版本和 Office/WPS 验收方式已写入[周通报 Word/Excel 输出字段与版式规格](2026-11-07-weekly-report-output-spec.md)。用户补充样例文件仅供版式参考，故输出字段可以多于样例列，但必须来自已确认报告数据版本。指标公式、倍数、输入冻结时点及不统计缺检等决定见[指标实施方案第 1–6 节](2026-11-07-weekly-report-indicator-statistics-plan.md)；文件仅呈现快照中的值。

本轮盘点确认：

1. 八类通报的首期记录字段能够从当前 `Record` / `RecordDetails` 投影读取；样例里的教师、班级应到/实到、比率、公共区域等字段不能因此视为已有契约。
2. Excel 样例只有六张表；Word 中有 17 张表，包含当前代码没有快照支持的统计和固定纪律文案；具体差异与空数据规则已记录在字段规格中。
3. 本轮周通报数据版本纳入用户已明确的本周指标及班级/全周汇总；学期累计留待项目阶段四，综合排名不纳入本轮。次数型违纪计入值按教学周倍数折算，distinct 人数和真实出勤率不倍增；倍数和结果在草稿生成时冻结。

已确定的输出边界：事件级和指标级倍数/计入值只读所选版本快照；内部文件可以显示快照中的学号和来源单位并受服务端导出权限控制；v1 不复制样例历史政策正文/落款；文件命名使用数据阶段、报告版本和生成时间；兼容性采用标准 OOXML，目标 Office/WPS 在阶段五实测。输出仍必须显式绑定不可变报告版本、数据阶段和格式。

**完成条件：** 基础字段与版式基线已满足，指标代码已加入数据版本和页面；`gofmt`、`go vet`、前端 ESLint、TypeScript 构建和 Vite 生产构建已通过。计算/快照回归、迁移 041 在一次性数据库的前置验证及模板 v3 环境发布尚待完成，完成后再把指标数据层标记为已验收并进入阶段 2 文件状态契约。不得在输出生成时临时计算指标。

### 阶段 2：确定输出服务和文件状态契约（指标数据层完成后）

**目的：** 定义输出任务的授权、版本关联、恢复和存储规则。

需要设计并评审：

- 输出产物关联报告、不可变版本、数据阶段、格式、模板版本、生成者、时间、校验值和对象存储文件引用。
- 输出任务至少能区分等待/生成中/可用/失败；失败保留安全诊断码并允许重试。重试不会覆盖此前可用文件或改变报告状态。
- 生成、查看、下载分别执行服务端授权；不得用 `REPORT_FINALIZE` 或 `ARCHIVE_VIEW` 代替生成/下载权限。
- 私有对象存储中不暴露 object key 或真实路径；下载时重新核对用户对报告版本的范围权限，并写访问审计。
- 数据库迁移只在现有表无法满足任务状态、重试和版本追溯时新增；不得改写历史迁移。
- API 契约使用明确的版本、阶段和格式参数，并通过幂等键/唯一约束防止重复副作用。

**完成条件：** API 契约、数据结构、错误码、授权动作、幂等方式和对象存储失败恢复方案经评审；如需要新依赖或外部服务，先取得明确确认。

### 阶段 3：实现后端生成、读取和下载

**范围文件：** `server/internal/reporting/`、`server/internal/httpapi/reporting_handlers.go`、`server/internal/httpapi/router.go`、`server/internal/store/` 中报告版本文件仓储、`server/internal/storage/`；只有需要时新增只追加迁移。

实现顺序：

1. 从指定不可变版本读取生成所需字段，构建按检查类型区分的 Word/Excel 内容；不查询可变的“当前记录”覆盖历史版本。
2. 调用已批准的模板/渲染实现生成文件，保存到私有对象存储，并记录版本关联、模板版本、校验值和任务状态。
3. 提供独立的生成、状态读取和下载接口；错误返回稳定错误码，不泄露对象路径、SQL 或敏感原文。
4. 为生成失败、存储不可用、文件缺失/校验不符和重复请求提供恢复/重试路径。
5. 验证任何输出操作都不改变报告状态、`rowVersion`、数据快照、审核轨迹或来源锁定。

**完成条件：** 一次性 PostgreSQL 和独立对象存储上的 API 集成验证覆盖授权、版本绑定、内容映射、幂等、失败重试、文件校验、越权拒绝和审计；对同一版本重试不会破坏已有可用产物。

### 阶段 4：接通工作台与归档

**范围文件：** `web/src/entities/reporting/model/reporting.ts`、`web/src/shared/api/reportingApi.ts`、`web/src/features/reporting/model/queries.ts`、`web/src/features/reporting/ui/WeeklyReportWorkflowPanel.tsx`、`web/src/pages/report/WeeklyReportArchivePage.tsx` 及相应测试。

实现要求：

- 仅针对用户明确选中的版本发起输出；归档详情切换版本后，文件操作随所选版本更新。
- 文案使用“按草稿数据生成 Word/Excel”或“按定稿数据生成 Word/Excel”，避免把文件称为定稿。
- 分开显示报告数据状态与文件状态。文件未生成/失败时不显示可下载入口，但不隐藏或回退已定稿数据。
- 覆盖生成中、成功、失败重试、下载失败、权限撤销和切换版本时的加载/空/错误状态。
- 生成和下载按钮只表达输出能力，不触发报告审核、定稿、发布或数据修正。

**完成条件：** 前端契约校验不接受缺字段/畸形文件状态；工作台和归档均能明确展示文件属于哪个报告版本；失败重试不丢失选择和数据状态。

按 `AGENTS.md` 对后端、前端和跨层改动执行相应完整检查。只报告本轮实际运行的命令和结果；隔离浏览器结果不能替代目标角色验收。

## 总体完成定义

1. 数据定稿仍只由报告状态机、权限、来源指纹和版本号决定；输出文件缺失、失败或重试不改变数据状态。
2. 每个 Word/Excel 文件都能追溯到明确的数据版本、阶段、格式及模板版本，且内容与该版本一致。
3. 文件生成、读取、下载有独立权限、审计、完整性校验和失败恢复；文件不可用时不显示为可下载。
4. 工作台、归档、API、数据库和当前规则文档均采用“数据状态”与“文件状态”分离的语义。
5. 真实环境和角色验收单独记录；代码通过不等于已部署或已验收。
