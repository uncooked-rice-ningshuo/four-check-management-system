# 到课率编辑、软删除与批量删除：实施决策

状态：授权方式已由用户确认，到课率增量已实现；不替代阶段 2 总计划。

## 实施前基线（历史）

- 当前分支 `feat-0.1-2`，在现有工作区操作。
- 已有到课率列表、Excel 导入、手工新增草稿、工作台；尚无记录编辑、删除或批量操作接口。
- 主表已经有 `row_version`、`deleted_at`、`created_by`、`submission_id`、`locked_by_report_id`，本轮能力可优先复用，不必为版本和软删除新增迁移。
- 当前权限动作只有检查录入、查看、审核、导出、汇总，没有独立的记录管理动作。普通成员与部门管理员均可从 `can_enter` 映射取得录入权。
- [阶段 2 角色矩阵](./2026-08-30-phase-two-completion-implementation.md#4-阶段-2-总体验收矩阵)要求普通成员只能修改自己的可编辑草稿，部门管理员可管理其有效范围内的记录。因此不能把 `INSPECTION_ENTER` 直接作为修改他人记录的依据，也不能静默把审核权当作修改权。

## 已确认授权方式

用户确认：增加独立“管理检查记录”权限；录入权可处理本人草稿，管理权可处理范围内他人草稿。

- 新动作 `INSPECTION_MANAGE` 可单独允许/拒绝。部长、副部长在部门配置允许录入的类型范围内默认获得管理动作，普通成员不默认获得。
- 本人记录需要 `INSPECTION_ENTER` 或 `INSPECTION_MANAGE`；他人记录需要 `INSPECTION_MANAGE`。每个动作分别计算 ALLOW 扣除 DENY，再取两条授权路径的并集；管理动作的拒绝不撤销独立存在的本人录入授权。超级管理员沿用既有权限。
- 编辑和单条/批量软删除使用相同授权规则，仅处理未提交 DRAFT。RETURNED 等其他状态，以及已有提交/通报锁定关联的记录一律拒绝。
- 编辑允许调整表单中的归属字段，但服务端必须同时授权原范围与目标范围；创建人、来源、导入关联和创建时间保持不变。
- 前端显示、部门筛选和请求体中的身份信息不能替代服务端鉴权。

## 已确定、不依赖授权选项的技术要求

1. 保持 `Handler → Application Service → Repository`。Handler 只绑定/输出；应用服务决定用例、权限与审计；仓储原子保存。
2. 按 ID 获取记录时，将有效学年、学期、周次、类型、部门、班级、年级及 ALLOW/DENY 编译到 SQL。不能先读取敏感记录再决定是否允许访问。不存在和无权访问统一使用安全错误策略。
3. 更新/删除必须提供正整数版本；SQL 同时限制 ID、原版本、数据范围和未删除条件，成功后递增 `row_version`，冲突返回 409，不能覆盖他人修改。
4. 已确认、已锁定、待审核记录不能通过普通 CRUD 修改；锁定关联字段和提交关联也必须核对，不能只看状态字符串。退回记录需要同步提交信息，待部门流程能力明确后接入，不能直接更改而遗漏提交聚合。
5. 编辑复用到课率字段/基础数据/日期校验。重复检测需要排除记录自身，同时保留数据库唯一索引拦截与其他记录冲突。不能沿用新增时生成新 ID、改写来源/创建人或清除导入关联的逻辑。
6. 修改归属范围时必须验证原范围和目标范围；是否允许修改学期、周次、部门等归属应在最终交互中明确，不能只验证客户端提交的新范围。
7. 删除仅设置 `deleted_at`，保留原明细、导入批次及历史审计。批量请求携带每项 ID/版本；固定锁定顺序，在单事务中全部鉴权、校验后执行，任一越权/锁定/冲突使整批零改动。
8. 编辑/删除审计保留前值、后值、原因、人员、时间与记录 ID，敏感文本按最小必要原则处理；审计失败使业务事务回滚。
9. 页面内提供编辑操作和删除确认，批量删除展示影响数量。403/409 明确提示，409 刷新列表和工作台，编辑失败保留表单输入。确认/锁定数据不出现可操作按钮，后端仍独立拒绝。

## 实施与验收顺序

1. 定稿动作与角色授权矩阵，同步权限服务及权限配置页面；先覆盖普通成员本人/他人、管理员范围、显式允许/拒绝。
2. 先写服务端回归测试，再实现按范围读取、编辑、软删除与单事务批量删除；沿用总计划的 PATCH `/api/v1/inspections/:id`、DELETE `/api/v1/inspections/:id`、POST `/api/v1/inspections/batch`，当前仅接收到课率类型。
3. 补前端编辑、单条和批量删除，并验证加载、权限、确认、失败及版本冲突。
4. 用一次性 PostgreSQL 数据库验证权限谓词、重复键、自身排除、版本冲突、部分失败回滚与审计一致性；不在业务库试验。
5. 执行两端聚焦和完整检查；涉及实际并发测试时补 `go test -race ./...`，同步交接记录，仍不关闭七类检查的总门禁。
