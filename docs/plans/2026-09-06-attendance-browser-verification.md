# 到课率与工作台浏览器复验（2026-09-06）

> 本文是 09-06 局部浏览器验收记录，不是当前运行状态或二阶段总验收。后续本地联调和最新缺口见[项目状态](../project-status.md)。

## 范围与环境

本轮按交接清单补当前到课率 CRUD、角色权限及工作台的真实浏览器验收。在 `feat-0.1-2` 现有工作区执行，没有修改运行时代码、依赖或迁移，没有提交、推送或部署。

使用当前源码编译 Go API、Vite 开发服务器及 Playwright CLI 的独立 Chromium 会话。PostgreSQL 16 为本轮新建的一次性容器，通过 `TestManualAttendancePostgresIntegration` 在空库应用 001–011 并生成虚构学生、班级、课程与记录；业务数据库未修改。账号使用随机临时密码，不保留凭据或会话。

初始测试周为 6 月历史周，首先验证无当前周；CRUD 操作完成后，将一次性夹具的周日期调整为 8 月 31 日至 9 月 6 日以验证工作台。批量冲突用例直接调整一条测试记录为 CONFIRMED，属于模拟并发状态变化的夹具操作，不表示部门审核流程已实现。

未启动 MinIO。本轮只验证导入抽屉目标选择门禁，不验证上传、预览、确认入库或文件完整性。

## 已通过的浏览器场景

| 场景 | 实际结果 |
| --- | --- |
| 普通成员无当前周 | 工作台明确提示未匹配周次；不使用其他周或模拟数字，列表要求选择学期周次 |
| 部门留空查询 | 选择测试学期周次后可查询全部有效范围，不自动回填主部门 |
| 本人草稿编辑 | 回填日期、北京时间、基础字段；未填写原因不能提交；成功将学时 2 改为 3，版本 1→2，新增更新审计 |
| 他人草稿保护 | 列表同时有本人 1 条、部长 2 条草稿时，成员仅有 1 组编辑/删除按钮 |
| 真实版本冲突 | 独立部长 API 会话先成功修改为版本 3；旧浏览器表单连续两次保存均被拒绝，保留学时 5 和原因，并提示重新打开核对 |
| 单条软删除 | 必须填写原因和二次确认；成功后列表排除记录，保留明细及删除审计 |
| 浏览器新增 | 外层部门留空时，抽屉独立选择目标部门；错误班级与学号不匹配被拒绝且保留输入，修正班级后创建成功 |
| 部长管理成员草稿 | 部长浏览器显示 3 组操作，实际编辑成员草稿成功；不改写原创建人 |
| 批量状态变化 | 已选择 3 条后模拟其中 1 条已确认；整批请求拒绝，仍为 3 条有效记录、1 条此前单删记录，删除审计仍为 1 条 |
| 已确认状态保护 | 重新加载后已确认记录无编辑/删除按钮，不参与全选；超级管理员同样不能编辑 |
| 批量成功 | 重新选择剩余 2 条草稿并确认后成功；最终 1 条有效已确认、3 条已软删除，4 条明细均保留，删除审计共 3 条 |
| 工作台计数 | 删除前部长本人待办/草稿为 1，部门到课率整体为 3（草稿 2、已确认 1）；删除后草稿 0、已确认 1、状态已完成 |
| 局部 DENY | 为部长加入班级级 INSPECTION_VIEW 拒绝后，到课率部门整体卡片隐藏，列表不返回被拒绝记录；其他授权类型仍显示 |
| 系统管理员 | 无检查授权的 ADMIN 仅有配置入口，直接访问检查路由显示 403；仍可进入统一工作台 |
| 超级管理员 | 无部门绑定仍可进入到课率、查询记录；URL 不被强制加入部门筛选 |
| 导入抽屉 | 外层部门留空可打开抽屉；目标部门初始为空，未选择时下载模板与上传预览按钮禁用，范围按名称展示 |

数据库最终核对：`INSPECTION_RECORD_CREATED=4`、`INSPECTION_RECORD_UPDATED=3`、`INSPECTION_RECORD_DELETED=3`；共 4 条记录及 4 条明细，1 条有效记录为 CONFIRMED。
