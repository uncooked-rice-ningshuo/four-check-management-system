# 学期适用年级与全量班级指标改造方案

> 2026-11-08 本地实现。学期配置、名册范围与预览、V2 快照、来源状态及越界校验已实现；042/043 迁移与工作流在一次性 PostgreSQL 验证。隔离 PostgreSQL/MinIO、真实 API/Vite、Chrome 的[39 项浏览器回归](../../output/playwright/86ee091938/summary.json)已通过，包含年级范围真实预览、保存及重开回显。本机数据库已实际应用 042/043，目标环境未部署，实际业务数据范围核查与真实账号角色验收仍待完成。

## 1. 目标与已核对的现状

- 每个学期明确选择纳入通报的年级。周次默认继承所属学期配置，不按年级名称或创建时间自动取“最新四个”。年级数量由实际教学范围决定，界面可以提示通常为四个，不在数据库写死四个。
- 每个被纳入的检查类型均展示该学期范围内的全部班级，包括没有违规记录、没有学生的班级。显示零值的前提是来源已确认；没有已确认来源时明确显示“待确认/未提交”，不能把缺数据解释为零违规或 100% 出勤。
- `server/internal/store/reporting.go:193-300` 当前读取全库启用年级、班级和在读学生；没有学期范围。`server/internal/reporting/indicators.go:55-63` 已预建输入快照里的班级行，`web/src/features/reporting/ui/ReportVersionIndicators.tsx:35-41,203-216` 也没有按违规记录筛班级。因此“只看到有违规记录的班级”不能仅靠改表格解决，需先定位目标版本、基础数据启用状态和实际名册输入。
- 现有 8 类计算只有到课率、早签出勤率的分母直接来自名册；其余按版本所纳入的有效记录计数。指标类型目前由 `ReportCountRow` 推出，缺少对应来源的类型可能完全没有标签页。受限范围版本不生成全周指标；历史无指标快照版本不从现值回算。

## 2. 范围模型和配置

### 2.1 学期年级配置

追加迁移建立 `semester_report_grades`：`semester_id`、`grade_id` 组成主键，均为受外键保护的 UUID；记录创建/更新人、时间和配置版本/审计。不要在 `grades.enabled` 上承载学期归属，历史年级可留在基础数据中。可另外在 `semesters` 或专门的配置主表记录乐观锁 `version`，以支持一次提交整个年级集合并防止覆盖。

在“学期与周次”页的学期设置中提供多选年级、所选年级下班级数和在读人数预览。选项覆盖年级分页，显示完整名称。只有现有学期配置管理权限可写；通报生成权限不自动授予配置权。写入服务校验学期、年级存在且不重复，集合非空；变更记录操作者、原因、前后集合和版本号。新学期可从前一学期预填候选，但必须由用户显式保存；周次只读显示“继承自学期”。

历史学期不自动按“最新四个”回填。上线前使用只读预览列出各学期的候选年级、班级及人数，由有权人员确认后写入配置。配置缺失时通报草稿生成返回稳定的“学期年级未配置”错误码，页面给出去配置入口；历史已保存版本仍按其原快照只读展示。

### 2.2 班级与学生范围

草稿生成时在同一事务内读取：该学期配置的年级 ID、这些年级下的启用班级，以及这些年级下 `enabled=true`、`enrollment_status='ENROLLED'` 的学生。班级查询用年级配置驱动，保留零学生班级；学生未分班或所属班级停用者仍计入年级总人数，但在预览中单列异常人数，不能悄悄造成班级合计与全周合计不符。年级配置保存后即使年级基础数据被停用，历史配置与既有版本仍保留；新版本生成前须明确检查配置有效性和停用影响。

这个阶段的名册仍是**草稿生成时的当前名册**，不能声称可以还原任意历史周。若要求历史周分母精确回溯，需要后续建立按周生效的学生在籍/转班记录或周名册快照。不能用当前 `students` 状态自动回写旧报告。

## 3. 指标快照和全量班级矩阵

### 3.1 版本数据

扩展 `ReportMetricInputs`，保存适用年级 ID/名称、班级 ID/名称、各年级及班级应到人数、配置版本和快照生成时间；保留原有周倍数与早签日期。统计规则版本升为 `WEEKLY_INDICATORS_V2`。旧 `V1` 版本继续按原 JSON 读取，不做原地修正或自动补算。修正、纳入、排除产生新版本时沿用该报告已冻结的范围与名册输入，除非通过现有“重新生成草稿”流程明确创建使用新配置的版本。

将班级行的身份键改为班级 ID，展示名称仍用快照名称；避免同名班级合并。全周分母从配置年级的学生总数计算，班级分母从对应班级人数计算。先用所有纳入班级预建指标行，再将版本内记录按其快照班级 ID 聚合；未匹配班级、超出学期年级范围、缺少学生身份或“违纪人数大于应到人数”应形成可操作的校验失败，不生成貌似正常的比率。多责任班级记录延续现行逐班归属规则，并对全周去重人数另行计算。

### 3.2 八类类型与零数据状态

指标明细以学期适用班级为行，以八类已配置参与通报的检查类型为标签页；每页都取同一份班级全集，允许零学生班级。类型是否出现由检查类型配置决定，不由本周是否存在违规记录决定。每个类型/班级至少携带 `sourceState`（已确认有记录、已确认零记录、来源未完成/未覆盖）；数值为零只表示**该版本中该班已确认来源没有对应违规事件**，不能推断实际完成了逐班检查。

当前零记录回执的粒度是提交单位×检查类型，不是班级。若业务要求逐班证明“已检查且无违规”，需要单独扩充逐班完成证据；本改造不伪造这层证据。对强制生成或来源不完整的版本，受影响类型/班级的比率和“零违纪”显示为不可计算/待确认，并保留强制生成原因。全院卡片只在完整授权与完整来源口径下展示全周结果，沿用现有受限版本保护。

八类现有公式保持不变：到课率按本周有缺课记录的去重学生数与学期适用名册人数计算；早签按适用人数×实际计划日期数计算；其他项目按已纳入记录及周倍数计算。新增班级行不能把“无记录”当作检查合格。卫生合计仍只在对应两类都纳入时计算。

本地接口：`GET/PUT /api/v1/admin/academic/semesters/:id/report-grades` 读取和以 `version` 乐观锁替换年级集合；`GET /api/v1/admin/academic/semesters/:id/report-grades/preview?gradeId=<UUID>` 可重复传入年级 ID，返回当前启用班级、在籍学生及未分入启用班级人数。预览不保存名册，新版本生成时重新读取并冻结。配置缺失返回 `REPORT_GRADES_UNCONFIGURED`，旧版本继续只读其原快照。

## 5. 实施顺序与验收

1. **现状复核**：对用户所见版本只读核查 `inputs.classes`、基础数据启用状态及页面行数，记录“为何只见有违规班级”的实际原因；避免用新方案掩盖独立缺陷。
2. **配置与迁移**：追加表、权限和审计；在一次性 PostgreSQL 验证迁移与学期配置 API。旧学期无配置时明确失败，新学期配置一次后所有周次继承。
3. **名册与指标**：用真实 PostgreSQL 回归覆盖历史年级留存、同名班级、零学生班级、未分班学生、停用班级、无违规班级、跨范围记录、缺配置、版本重算及失败回滚。
4. **页面与浏览器**：验证八类标签页均显示相同的学期班级全集；有记录、已确认零记录、未提交三种状态可区分；筛选/分页/滚动、工作台与归档、管理员与受限角色路径均用真实 API 检查。
5. **交付门禁**：Go 格式化、`go vet ./...`、`go test ./...`；按仓库锁定的 Node/pnpm 工具链运行 `pnpm lint`、`pnpm test`、`pnpm build` 及匹配的浏览器回归。迁移、API、页面、真实环境、角色验收分别记录，不把代码实现视为已部署。

## 6. 需要在实现前确认的业务边界

- 是否允许未分班在读学生计入全院分母（现行实现允许），以及班级人数合计不等于全院人数时的页面说明。
- 对“班级已确认零记录”是否要求逐班检查完成证据；现有提交单位×检查类型的零记录回执无法证明每个班均被检查。
- 学期内新增/停用班级及学生转入转出，是否从某个周次起生效。若要求准确历史回溯，需要补充有效期或周名册快照，不能仅靠学期年级关联解决。
